### 2.2 P1 — RPC 권한 검사 누락 (4건)

**파일**: `uniqn-mobile/supabase/migrations/20260414130500_recover_stats_increment_rpcs.sql`

| RPC | line | 누락 검사 | 영향 |
|-----|------|----------|------|
| `increment_view_count(posting_id)` | 9-17 | `auth.uid()` vs job_postings.owner_id 또는 service_role 제한 | 임의 사용자가 무한 view inflate → ranking 오염 |
| `increment_announcement_view_count(p_announcement_id)` | 25-33 | 동일 | 동일 |
| `increment_template_usage(p_template_id)` | 41-49 | 동일 | 통계 신뢰 저하 |
| `get_job_posting_stats(p_owner_id)` | 59-75 | `auth.uid() = p_owner_id` 검사 | **타 employer 통계 정보 누출 (총 지원자 수, 마감 수 등 비즈니스 인텔리전스)** |

**Reviewer A는 P0로 등급화**. 본 리뷰는 다음 이유로 **P1로 하향 조정**:
- view_count 류는 vanity metric (financial impact 없음 가정 — 단 ranking 알고리즘이 view_count 의존하면 P0)
- get_job_posting_stats는 information disclosure지만 PII가 아닌 비즈니스 메트릭 → P1

**권고 fix**: 별도 마이그레이션 `2026041xxxxxxx_add_permission_checks_to_increment_rpcs.sql`
```sql
CREATE OR REPLACE FUNCTION public.get_job_posting_stats(p_owner_id uuid)
RETURNS TABLE(...) LANGUAGE plpgsql STABLE SECURITY DEFINER AS $$
BEGIN
  IF auth.uid() != p_owner_id AND NOT public.is_admin() THEN
    RAISE EXCEPTION 'unauthorized';
  END IF;
  RETURN QUERY SELECT ...;
END;
$$;
```
- increment_* 3개는 SECURITY DEFINER 그대로 두되 `WHERE id=p AND (owner_id=auth.uid() OR public.is_admin())` 유사 패턴, 또는 RPC 자체를 service_role 전용으로 회수하고 client에서는 호출하지 않도록 제거.
