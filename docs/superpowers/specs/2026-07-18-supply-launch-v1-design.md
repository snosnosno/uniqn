## 1. 왜 이 범위인가 (실사용자 0의 함의)

- **증분 출시·리텐션 프로브 게이트가 무의미** — 잴 사용자가 0이므로, 제품 렌즈의 "grid 투자를 리텐션 신호에 게이트하라" 권고는 성립하지 않는다. → 완결된 한 덩어리를 한 번에.
- **이 배치는 "공급측(사장·대회사) 경험 완결"이지 "수요측(딜러) 획득"이 아니다.** 딜러가 앱에 없으면 사장은 공고를 올려도 지원 0. 딜러를 앱 밖에서 데려오는 유일한 장치가 이미 만든 **공유+OG**뿐이며, **수요측 획득은 이 배치가 풀지 못하는 별도 존재적 숙제**임을 명시한다(§6 비목표).
- 3렌즈 판정 요지 반영: 공유가드+OG=핵심 성장 루프(전원) · "워크스페이스" 노출=1순위 사장 마찰(사장 HIGH) · 그리드=이중입력 제거 시에만 생존(사장·제품).

## 2. "워크스페이스" → "팀" 전역 rename (신규, 문자열 전용)

### 2.1 결정
- 사용자 노출 문자열 **"워크스페이스" → "팀"** 전역 교체. 계층은 **팀 ⊃ 지점**("운영처→지점"은 #270에서 이미 반영됨).
- **은닉(isSolo 조건부 숨김) 대신 rename을 채택한 이유**: "팀"은 단독 사장도 이해하는 자연어("나 혼자인 팀")이고 초대·협업 프레임과 자연스럽게 맞는다. 못 알아듣는 단어를 **숨기는 장치(isSolo 분기 + 전환 칩 + 테스트)를 새로 만드는 것보다, 알아듣는 단어로 바꾸는 것이 더 싸고 부작용이 없다.** owner2 렌즈가 HIGH로 지목한 "⋯ 메뉴 첫 줄 워크스페이스" 마찰이 은닉 없이 해소된다.

### 2.2 적용 지점 (구현 시 전수 grep으로 확정)
- ⋯ 메뉴 라벨: `{ label: '워크스페이스', value: 'workspace' }` → `{ label: '팀', value: 'workspace' }` (`app/(app)/(tabs)/employer.tsx`) — **value·라우트 불변**.
- 에러 문구: "워크스페이스를 불러오지 못했어요" → "팀을 불러오지 못했어요" (`app/(employer)/weekly-grid.tsx` 등).
- 워크스페이스 화면(`app/(employer)/workspace/index.tsx`) 타이틀·헤더·본문·안내 문자열.
- 그 외 사용자 노출 "워크스페이스" 전부(placeholder·accessibilityLabel·toast 포함).

### 2.3 규칙
- **화면 문자열만** 교정. 변수명·함수명·라우트(`/workspace/*`)·주석·테스트 픽스처의 코드 개념어는 불변.
- accessibilityLabel도 함께(스크린리더 일관).
- 기존 테스트가 옛 문구를 assert하면 새 문구로 동반 갱신.

### 2.4 검증 (구현 시)
- 전수 grep `워크스페이스`(화면 문자열) 잔여 0.
- **기존 "팀" 단어 사용처 충돌 grep** — 다른 도메인에서 "팀"을 이미 쓰면 보고 후 조정(신규 리스크 방지).
- 렌더 테스트: 옛 문구 assert → 새 문구.

### 2.5 비목표
- isSolo 조건부 숨김(메뉴/선택기 비노출) — rename으로 대체, 하지 않음.

## 3. grid-auto-sync (기존 스펙 채택)

- **진실원: `docs/superpowers/specs/2026-07-18-grid-auto-sync-design.md`** (D1~D4, 리스크, 테스트 전략).
- 본 배치에서 재확인·확정한 결정:
  - **D1 즉시성 우선 자동 연결** — 비-대회 공고 등록 시 기본 지점에 `venue_id` 자동 연결(멱등 `get_or_create_venue_container`). dormant 컨테이너는 무해·멱등이며, 그리드 접근 시 파생값이 준비돼 있는 의도된 부수효과. ("지점 존재 시에만 연결" 완화안은 기각 — 첫 그리드 진입 시 빈 화면이 오히려 이탈 유발.)
  - **대회(tournament) 공고 제외** — 그리드는 홀덤펍 주간 도구, D-7 버스트 대회는 비대상(`venue_id` NULL 유지).
  - **읽기 시점 파생**(demand 테이블·트리거 기각) + **seat 좌석 합** 컨벤션(seat-basis와 일치).
- **선행 의존 충족**: seat-basis(`#269`)가 이미 master 머지·prod 적용됨 → grid-auto-sync 착수 가능.
- 출시 시 `weekly_grid_enabled` ON(이 배치로 그리드를 처음 켠다).

## 4. 통합 · 원자적 출시

### 4.1 빌드 전략 (채택안 B)
`#270`을 먼저 머지 → **최신 master에서 새 브랜치 `feat/team-rename-grid-autosync`** 로 §2·§3 구현 → 머지. "한 번에 출시"는 코드 머지가 아니라 **배포 타이밍**(OTA·CF·flag)을 묶어 달성한다(리뷰 단위는 작게 유지). 실제 구현은 병렬 세션 격리 규칙에 따라 워크트리로 분리.

### 4.2 출시 순서 (전부 사용자 게이트 — 자동 진행 금지)
1. **prod DB 마이그**(grid-auto-sync) — `weekly_grid_enabled` OFF라 변경 RPC(`get_venue_grid_summary`) 호출 0 → **언제 적용해도 안전**. MCP `apply_migration` 전용.
2. **OG용 CF env**(`SUPABASE_URL`/`SUPABASE_ANON_KEY` 공개값) 등록 + web 재배포 + 크롤러 UA curl 실측.
3. **OTA**(신규 클라 — 공유 가드·팀 rename·`venue_id` 쓰기).
4. **`weekly_grid_enabled` ON** (맨 마지막 — 역순이면 구 클라가 새 RPC 반환 형태를 못 받아 깨진다).

## 5. 테스트 전략

- **§2 팀 rename**: 교정된 문구 렌더 테스트(옛 문구 → 새 문구). 잔여 grep 0 + "팀" 충돌 grep.
- **§3 grid-auto-sync**: grid-auto-sync 스펙 §6 승계 — pgTAP(날짜별 Σ count 파생·fixed 제외·대회 미포함·반환 계약) / `serialization` 단위(단독=자동 venue_id, 대회=NULL) / `buildGridCells`·`gridSlotState` 병합(max) / repository requiredCount 매핑 / Red-Green(일반 공고 0으로 안 잡힘 → 연결+파생 후 반영).
- **회귀**: 지금레인 #270 기존 테스트(canShareJob·useShare·ogHtml·⋯ 메뉴·설정 섹션 제거) 유지.
- 완료 게이트: `npm run quality` 0/0/OK + 관련 jest PASS(실행 증거).

## 6. 비목표 (Non-goals)

- **isSolo 조건부 숨김** — §2 rename으로 대체.
- **홈 "이번 주 채우기" 스트립** — 그리드가 실제로 쓰인다는 사용 신호가 나온 뒤로 유예. 그리드는 기존 "이번 주 근무표 열기" 진입 버튼으로 접근.
- **대회사 승인 SLA/화이트리스트** — 대회사 렌즈 HIGH(D-7 골든타임 × 승인 대기 공유 차단). 별도 트랙.
- **딜러(수요측) 획득·리텐션** — 제품 렌즈 HIGH 맹점. 이 배치가 풀지 못하는 별도 존재적 숙제.
- `og_image_url` 업로드 UI(dormant 컬럼) · 역할별/시간대별 필요 인원 분해 · demand 테이블.
