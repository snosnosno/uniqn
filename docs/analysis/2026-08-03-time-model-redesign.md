# 시간 모델 재설계 — 단순·직관 정본화 (2026-08-03)

> 목적: 근무 시간 모델을 **직관적이고 단순하게** 재설계하되 모든 기능이 문제없이 동작하도록 한다.
> 근거: Explore 실측 4회(복사 체인·컬럼 전수·클라 소비자 전수·DB 함수 전수) + 사용자 도메인 결정 1건.
> 상태: **설계 문서** — 구현 전 사용자 승인 대상. 구현 세션은 전용 워크트리에서(메모리 규칙).

---

## 0. 확정된 도메인 결정 (사용자, 2026-08-03)

**예정 퇴근 시각은 만들지 않는다.** 당일알바·일용직 도메인이라:
- 스태프는 **출근 시각만** 알면 된다 (예정축 = 시각 하나)
- 정산은 **실제 출퇴근**(`check_in_ts`/`check_out_ts`)으로만 한다
- 예상 정산액은 사전 계산 대상이 아님 — "근무 후 확정" 표시(S2 처리)가 정답 UX

이 결정으로 기존 분석의 P1(예정 퇴근 부재)·P2(자정 넘김)는 **결함이 아니라 비문제**로 재분류된다.
자정 넘김은 종료 시각에만 생기는 문제이고, 종료 시각이 없으면 발생하지 않는다.
→ 메모리 `project_time_model_no_scheduled_end.md` 기록 완료.

## 1. 핵심 판정 — timestamptz 승격 폐기, text 'HH:mm' 정본 유지

원안(scheduled_start_ts/scheduled_end_ts 승격)은 **폐기**한다. 실측 근거:

| 근거 | 실측값 |
|---|---|
| prod 데이터가 이미 깨끗함 | work_logs 시간값 전수가 단일 'HH:mm'. 범위형('18:30 - 03:00')은 CHECK 허용에만 남은 레거시 |
| 승격 표면적이 과대 | DB 함수·트리거 9개 + CHECK 1개가 문자열 비교(`_posting_slot_key`)로 수렴, 클라 프로덕션 소비 지점 약 40곳, e2e 10 spec 하드코딩 |
| 승격 편익이 소멸 | 자정 넘김(종료 시각 전용 문제)이 도메인 결정으로 사라짐. 남는 편익은 "파싱 제거"뿐인데, 단일 'HH:mm'+NULL 로 통일하면 파싱은 `split(':')` 한 번으로 축소됨 |
| 정산은 이미 timestamptz | 실제축(check_in_ts/check_out_ts)은 Phase D 에서 정리 완료. 예정축은 정산에 관여하지 않으므로 타입 정밀도가 불필요 |

> 비유: 출근 시각은 "가게 문에 붙인 오픈 시간 안내"다. 초 단위 시계가 필요한 건 급여 계산(실제 출퇴근 타임스탬프)이지, 안내문이 아니다.

## 2. 재설계 — 시간 정본 3원칙

```
[원칙 1] 공고는 광고, work_log 는 계약        (표류의 의미론적 해소)
[원칙 2] 예정은 'HH:mm' 하나 또는 NULL 하나   (표현 통일)
[원칙 3] 쓰기는 RPC 만                        (재표류 차단)
```

### 원칙 1 — 공고는 광고, work_log 는 계약

복사 3단계(공고→지원서→work_logs)를 "동기화 없는 복사"가 아니라 **의도된 스냅샷 계층**으로 선언한다:

| 계층 | 의미 | 수정 시 효과 |
|---|---|---|
| `job_postings.schedule` | **광고** (모집 템플릿) | 수정해도 확정자에게 전파 안 됨. 이후 지원자에게만 적용 + 기존 확정자 알림(현행 notify 유지) |
| `applications.assignments[].timeSlot` | **신청 스냅샷** (지원 당시 조건) | 확정 전 이력. 확정 후엔 work_logs 와 함께 RPC 가 동시 갱신(#407) |
| `work_logs.time_slot` | **계약** (그 사람과 확정한 출근 시각) | **확정 후 시간 변경의 유일한 정본** — 근무표에서 편집 |

역방향·순방향 자동 전파 장치는 **만들지 않는다**. 대신:
- 확정자 시간 변경 = 근무표에서 `update_work_log_slot`(개인, #407 기존)만 사용 — **일괄 편집 RPC 는 만들지 않는다(사용자 확정 D2)**. ⚠️근거 정정(검토 반영): "확정 인원이 적다"는 **홀덤펍 세그먼트에만 참** — 대회사(D-7 집중, 수십 명 확정)에서 "전원 30분 변경 = 개인 편집 N회 + 알림 N발"이 되므로, 대회사 온보딩 시 이 결정은 재평가 대상으로 명시해 둔다
- 공고 시간 수정 UI 에 확정자 존재 시 안내 문구: "이미 확정된 N명에게는 적용되지 않습니다. 근무표에서 변경하세요" (+기존 알림)

이러면 원안 3단계(참조 모델 + 슬롯 안정 ID + jsonb 재설계)가 통째로 불필요해진다. 표류는 "고쳐야 할 버그"가 아니라 "광고와 계약은 원래 다른 문서"라는 도메인 사실이 된다.

### 원칙 2 — '미정' 표현 통일 (4종 → 최대 2종)

현행: `NULL` / `'미정'` / `'NEGOTIABLE'` / `''` 가 전부 CHECK 통과, 13개 파일이 제각각 분기.

| 값 | 처분 |
|---|---|
| `''` (빈문자열) | **폐지** — NULL 로 백필 |
| `'미정'` (TBA) | **폐지** — NULL 로 백필. "시간 미정" = NULL 하나 |
| `'NEGOTIABLE'` (고정공고 협의) | **폐지 — NULL 로 흡수(사용자 확정 D1)**. "협의" 문구는 공고 유형(fixed)에서 유도. 클라 `FIXED_TIME_MARKER`/`TBA_TIME_MARKER` 상수(types/assignment.ts) 제거 |
| `'HH:MM - HH:MM'` (레거시 범위) | **폐지** — 시작 시각만 남기고 백필, CHECK 에서 범위 패턴 제거 |

최종 CHECK: `time_slot IS NULL OR time_slot ~ '^([01][0-9]|2[0-3]):[0-5][0-9]$'` — **상태는 정확히 2개**(시각 확정 / NULL 미정).

**동반 필수 수정** — `application.schema.ts:177` 의 `timeSlot: z.string()` 을 `z.string().nullable()` 로. 이게 '미정' 문자열이 태어난 근본 원인(널 넣으면 지원서 레코드 통째 증발 사고)이므로, 백필 전에 클라 배포가 선행돼야 한다(순서 엄수).

효과: 13개 파일의 3중 분기가 `time_slot === null`(미정) 판정 하나로 수렴. `TimeNormalizer` 의 범위 파싱·마커 파싱 경로 삭제 → 파생값 계산이 "date + 'HH:mm' 결합" 한 줄로 축소.

### 원칙 3 — 쓰기는 RPC 만 (재표류 차단)

- #407 잔여 과제인 **직접 UPDATE REVOKE** 를 이 재설계의 마감 게이트로 편입 (웹 배포·OTA 후)
- `add_direct_staff` 경로(application_id NULL)는 현행 유지 — 원칙 1 에서 work_log 가 계약 정본이므로 지원서 부재가 문제되지 않음
- **RPC INSERT 시점 서버 정규화**(검토 반영): `confirm_application`·`add_direct_staff` 의 INSERT 에서 센티널('미정'/'NEGOTIABLE'/'')→NULL, 범위→시작시각으로 접는다. 구클라·구데이터·스냅샷 복원(`restore_original_assignments_on_cancel`)이 낡은 값을 재전송해도 신뢰 경계 한 곳이 전부 흡수 — **applications jsonb 백필이 통째로 불필요해지는 핵심 장치**

### 보강 — 실제축 출처 대칭 (소규모, 정산 분쟁 대비)

| 추가 | 내용 |
|---|---|

## 3. 실행 단계 (검토 반영 개정판 — R0 신설, 순서 엄수)

| 단계 | 내용 | 위험 | 선행 조건 |
|---|---|---|---|
| **R0 (신설)** | **서버 선행 마이그레이션 1건**: ① `_posting_slot_key` 에 'NEGOTIABLE'→'미정' 흡수(센티널·NULL 이 같은 키로 접히게) ② `confirm_application`·`add_direct_staff`·seat-basis 정원 CASE 의 `'NEGOTIABLE'` 리터럴 정합 ③ 두 RPC INSERT 에 센티널→NULL·범위→시작시각 정규화 ④ 확정자 대상 공고 변경 알림 문구·링크 분리("내 확정 시간은 변경되지 않음" + `/schedule` 링크, direct staff 수신 누락 해소) | **中** | 없음. **구클라 완전 하위호환 — R1 배포 전 필수** (없으면 fixed 공고 정원 검사 무력화 = 무제한 초과 배정) |
| R1 | zod nullable 화(읽기 관용) + 클라 '미정' **판정** 통일(13파일, `isTimeTBD` 헬퍼) + 클라 키 빌더 정합(`slotCapacity.ts`·`postingSurfaceModel.ts` + fixed 회귀 테스트 재작성) + 공고 수정 시 확정자 안내 문구 + D4 반영. ⚠️**쓰기는 '미정' 문자열 유지(null 전송 금지)** — 구버전 사장 앱의 엄격 zod 가 null 지원서를 증발시킴. ⚠️레거시 읽기 경로(센티널·범위형)는 삭제 금지 — prod 기존 행이 R3 까지 남음 | 中 | **R0 prod 적용 후** |
| R2 | R1 웹 배포·OTA | 低 | R1 |
| R3 | 마이그레이션(한 트랜잭션): `work_log_notify_update` 트리거 **비활성화** → work_logs 백필(`''`·`'미정'`·`'NEGOTIABLE'`·범위형→NULL/시작시각, 전 상태 행 포함) → 트리거 재활성화 → CHECK DROP/ADD **동일명** → start_time_source/clocked_in_raw 추가 + QR 체크인 RPC 재정의(`CREATE OR REPLACE` 만, `SET search_path` 명시) + end_time_source CHECK 는 NOT VALID→VALIDATE 2단계. **applications jsonb 백필은 하지 않는다**(R0 ③ 이 흡수). **+클라 후속 PR**: null 쓰기 전환('미정' 문자열 쓰기 폐지, `TBA_TIME_MARKER` 제거) + 레거시 읽기 경로(센티널·범위 파싱) 삭제. 동반: pgTAP `work_logs_time_slot_format.test.sql` 의 센티널 lives_ok→throws_ok 스왑(red 확인) + e2e 시드 Grep | 中 | R2 + 센티널 신규 기록률 실측 0 근접(서버 카운트 쿼리로 게이트 측정) |
| R4 | 직접 UPDATE REVOKE (#407 잔여와 합류) | 中 | R3 + 구버전 앱 공존 기간 종료 |

주의사항:
- 트리거 비활성화 없이 백필하면 **행마다 "시간 변경: 미정→미정" 오알림 대량 발송** (Case 2-B 가 `IS DISTINCT FROM` 만으로 발화).
- `clocked_in_raw` 기존 행 소급 백필 **금지** — check_in_ts 는 수기 수정됐을 수 있어 "원값 보존" 의미가 거짓이 됨. NULL 유지.
- QR RPC 재정의는 DROP 금지(`20260731090000` 이 회수한 PUBLIC EXECUTE 부활 위험) — `CREATE OR REPLACE` + search_path 명시.
- 23514 에러 매핑(`utils/supabase.ts:134`)에 "상대방 앱 업데이트 필요" 분기 추가 — 구클라 지원서를 신클라 사장이 확정하다 맞는 케이스는 사장이 고칠 수 없는 에러라 현행 문구("시간을 다시 선택해 주세요")가 오도.

- e2e: 10개 spec 의 `'18:00'` 하드코딩은 단일값이라 **즉시 충돌 없음**. R3 에서 CHECK 강화 시 e2e 시드 전량 Grep 확인(quality 사각지대 규칙).
- 에러 매핑: `utils/supabase.ts:130` 이 CHECK 제약명 `work_logs_time_slot_format` 을 문자열로 매핑 중 — R3 에서 제약 재생성 시 **같은 이름 유지** 필수.
- ⚠️ 구현 착수 전 `git pull` — 로컬 master 가 origin 대비 6커밋 뒤(#407 마이그 파일이 디스크에 없음, 실측 확인됨).

## 4. 사용자 확정 결정 (2026-08-03)

- **D1. `'NEGOTIABLE'` → NULL 흡수 확정.** 미정 상태는 NULL 하나. "협의" 표시는 공고 유형(fixed)에서 유도.
- **D2. 일괄 편집 자체 불필요 확정.** 신규 RPC 없음 — 개인별 편집(#407 `update_work_log_slot`)만으로 충분. (근거 정정은 원칙 1 참조 — 대회사 온보딩 시 재평가)
- **D3. 새벽 시작 근무는 실제 시작 날짜로 공고하는 관례 확정.** 코드 변경 없음, 공고 작성 화면 안내 문구만.
- **D4. 협의/미정 구분 표시 포기 확정(검토가 발굴, 사용자 확정).** 스케줄 화면은 전부 "미정"으로 표기 — 스태프 입장에선 둘 다 "아직 시간이 안 정해짐"이라 실용 차이가 작음. 배경: D1 의 "공고 유형에서 유도"는 배선이 없었음(`WorkTimeDisplay.getDisplayInfo` 입력에 공고 종류 부재, negotiable 판정은 센티널 문자열 비교뿐). R1 에서 negotiable 분기·가드 테스트를 '미정' 단일 표기로 정리.

## 5. 적대 검토 결과 (fable 2렌즈, 2026-08-03)

- 검토 체계: architect(설계 타당성)·database-reviewer(DB 안전성) fable 병렬, "옹호 금지·파일:라인 근거 필수" 지침.
- **골격(승격 폐기·NULL 통일·RPC 전용)은 양쪽 모두 타당 판정.** 실행 계획은 REQUEST CHANGES — 두 리뷰가 **독립적으로 같은 CRITICAL**(정원 키 불일치)을 지목해 §3 을 R0 신설 포함으로 개정함.
- 채택한 지적: 정원 키 불일치(CRITICAL, 무제한 초과 배정) · 백필 오알림(CRITICAL) · jsonb 백필 대신 RPC 정규화(HIGH) · pgTAP red-스왑 동반 · 확정자 알림 오도(공고=광고인데 링크가 공고로) · 게이트 측정화 · 문서 모순(bulk 문장) · 근거 오류(대회사).
- 기각한 지적: "restore_original_assignments_on_cancel 함수는 존재하지 않음"(design-critic) — **오탐**. `uniqn-mobile/supabase/migrations/20260727150000_...sql` 실재를 Grep 으로 확인(리뷰어가 레포 루트에서 탐색한 것으로 추정). 단 클라 이력 서비스 경유 복원 경로도 병존하므로 R0 ③ 정규화가 양쪽을 흡수한다는 결론은 동일.
- 잔여 확인 사항: #407 `update_work_log_slot` 본문이 로컬 디스크에 없어(6커밋 뒤) R0 작성 시 pull 후 정규화 규칙 정합 확인 필요.
