# UNIQN 코어 유저플로우 UX 품질 감사 (2026-07-10)

> 정합성·보안이 아닌 **UX·유저플로우 품질 렌즈**(마찰·막다른 길·어색함·상태 부재·정보구조·재설계 기회)의 감사.
> 같은 날 완료된 [실측 감사](2026-07-10-userflow-audit.md)(확정 24건, 보안·정합성 중심)와 **중복 없음** — 그 감사의 확정 목록을 전 에이전트에 재보고 금지로 주입했다.

## 한 줄 결론

**이 앱의 UX 부채 대부분은 "기능이 없어서"가 아니라 "이미 지어놓은 것을 배선하지 않아서"다.** 평점 배지·4단계 가입 인디케이터·알림 카테고리 설정 스토어·realtime 인프라·근무이력 리스트가 전부 코드에 존재하는데 화면에 연결되지 않았다 — 이 계열만 이어도 체감 품질이 한 단계 오른다. 구조 레벨에서는 **하나의 개념이 두 개의 시스템으로 쪼개진 곳**(이중 홈, 두 협업 모델, 검색/브라우즈 이원 규칙, 시간수정 이중 경로)이 사용자 정신모델을 반복적으로 깨뜨린다.

### 실측에서 정정된 것 (에이전트 보고를 그대로 믿으면 안 되는 이유)

1. ~~"마감/재오픈 UI 전무"~~ (ux-posting) → **거짓**. `JobPostingCard.tsx:112-140`에 마감(ACTIVE/CAPACITY_FULL)·재오픈(CLOSED) 버튼 실존. 살아남는 실체: 액션이 **목록 카드에만** 있고 상세 관리 허브에 없음 + 만료(expired) 상태엔 재게시 경로 없음.
2. ~~"탭으로 돌아가는 유일한 통로는 로고"~~ (ux-nav-ia) → **거짓**. `HomeTabBar`는 표시만 비활성일 뿐 `router.push`로 정상 네비게이션. 살아남는 실체: **탭→홈 복귀**만 무설명 로고 단일 경로 + 홈에서 현재 위치 활성 표시 부재.
3. ~~"useUnsavedChangesGuard 소비자 0건"~~ (ux-patterns) → **거짓**. `create.tsx:40`·`edit.tsx:65` 사용 중. 살아남는 실체: `ApplicationForm.tsx:211-232`의 문구 다른 중복 자체구현 + 일부 폼 미적용.
4. ~~"캘린더 4상태가 시각적으로 전혀 구분 안 됨"~~ (ux-schedule) → **과장**. `SCHEDULE_DOT_COLORS`(CalendarView.tsx:67-72)가 상태별 4색 배정. 살아남는 실체: 형태 동일·**색상 단독 의존**(색약 취약) + 지원중이 확정 일정과 같은 캘린더에 동급 표기되는 정신모델 혼합.

그 외 검증한 HIGH급 주장 17건은 인용 라인까지 전부 정확했다. 통계형 주장 2건은 수치 보정(confirmAction 채택 6파일 vs Alert.alert 직접 14파일 / `active:opacity` 169회 vs `active:bg` 83회) 후 방향성 유지로 채택.

## 2. 메타 루트원인 — 83건은 6개 패턴으로 모인다

### 패턴 ① 지어놓고 배선 안 함 (built-but-not-wired) — 최대 뿌리, 전 flow에서 반복

### 패턴 ② 완료 선언 ≠ 실제 상태 (false completion)

- 가입 "3/3 완료" 토스트 → 실제로는 뒤로가기 차단된 필수 profile-setup이 남음 ✅
- 지원 완료 안내가 **존재하지 않는 화면**("마이페이지") 지칭 ✅ (`ApplicationForm.tsx:380` — 탭 라벨은 구인구직/내 스케줄/게시판/내 공고/프로필)
- 공고 등록 성공 → 미리보기 없이 즉시 홈 `router.replace` ◐ (`create.tsx:83`)
- 한 화면에 "완료" 뱃지 2개(근무 완료 vs 정산 완료) — 라벨 무구분 ◐ (S2)
- 같은 `applied`가 화면 따라 "지원 완료" vs "지원 중" ◐ (`shared/status/types.ts:56-70`)

### 패턴 ③ 비가역 결정에 안전장치 없음 + 막다른 길

- **노쇼 처리 완전 비가역** — UI 게이트+데이터 모델 이중 차단, Undo 전무 ✅ (HIGH)
- 성별 set-once — 서버가 조용히 drop, 우회 안내(고객센터) 0줄 ✅ (`profileService.ts:89-101`)
- 공고 타입 선택 잠금 — 최초 선택 시점엔 "변경 불가" 경고 미노출(수정모드 `disabled`에서만) ✅ (`PostingTypeSelector.tsx:121-127`)
- 프로필 조회 재시도 소진 → 에러 화면·재시도 버튼 없이 침묵 방치("멀쩡해 보이는데 아무것도 안 되는" 상태) ✅ (`useAuthGuard.ts:193-199`)
- employer 신청 pending — 수정·취소 API 자체 부재, 최대 24h 대기 강제 ◐
- 취소요청 거절 — 푸시 1회 놓치면 흔적 증발(`isCancellationPending`만 존재, rejected 상태 필드 없음) ◐ (S6)
- QR 스캔 실패 — 수동 입력·수동 체크인 요청 등 대체 경로 0 (정산 기준 데이터인데) ◐ (S9)
- 리뷰 7일 마감 — 경고 없이 조용히 소멸 + 완료 근무 상세에 리뷰 CTA 0 ✅ (ScheduleDetailModal 무매치)
- 워크스페이스 멤버 자진 탈퇴 불가(제거 버튼 `isOwner &&`만) — 협업자는 "나가기" 있음(비대칭) ✅ (`workspace/index.tsx:321`)

### 패턴 ④ 결정 시점에 정보가 없음

- 확정을 실행하는 `applicants.tsx`에 정원 현황(X/Y) 0 — 허브로 되돌아가야 확인 ✅
- 수정 제한(`filledPositions>0`) 사전 고지 없음 — 진입 후 토스트로만 통보 ◐ (`edit.tsx:93-101`)
- staff 초대 시 "미가입"과 "role 부적격"이 같은 메시지 — 이메일 오타로 오인·반복 재시도 ✅ (단, role 필터 자체는 dead-end 예방 의도 주석 실존 → **수정은 메시지 구분만**)
- 다일차 공고 역할 인원 과소 표시(seed 날짜만 집계, `addToExisting=false`) — 대회사 페르소나 직격 ✅ (`draftAdapter.ts` buildDatedFormRoles)
- 검색 2자 미만 → 검색 미실행인데 "'X' 검색 결과가 없습니다" ◐
- 받은 초대 발견성 — 배지는 설정 깊숙이만, 매일 보는 내공고 탭 헤더 아이콘·워크스페이스 메인엔 신호 0 ✅ (invitations 링크 무매치)
- 개인정보 열람(`my-data`) 진입점이 **회원탈퇴 화면 안** 단 1곳 ✅ (전수 grep)

### 패턴 ⑤ 하나의 개념, 두 개의 시스템 (dual systems)

- **이중 홈**: 로그인 착지는 탭 밖 스택 화면 `/(app)/home`(가짜 탭바, 활성 표시 불가) vs 진짜 5탭. 탭→홈 복귀는 무설명 로고 탭 단일 경로 ✅(기전 정정 반영)
- **두 협업 모델**: 워크스페이스 멤버(수락 필수·전공고) vs 공고 협업자(동의 없음·단일공고) — 상호 언급 0, 초대 검색 UX도 2벌(정확 매칭 1회성 vs 실시간 debounce) ◐
- **검색 vs 브라우즈**: 타입 칩이 검색에 미적용(의도적 트레이드오프 주석 실존)인데 칩은 활성으로 보임 — 죽은 컨트롤. 날짜 필터는 반대로 적용됨. 지역 필터는 검색 시 조용히 소멸 ✅ → 수정 방향은 재적용이 아니라 **검색 모드에서 칩 비활성 시각화**
- **시간수정 이중 경로**: 정산탭은 사전 가드(`payrollStatus===PENDING`)+구체 에러, 스태프관리탭은 가드 없이 폼 전부 채운 뒤 서버 거부+일반 에러 ✅
- **staff/employer 뷰 전환 3곳 3규칙**: 홈 수동 토글 / 내공고 자동 판정 / 구인구직 무관 ◐
- 공고 폼 IA가 타입별 분기: fixed만 평면 역할 섹션, 나머지는 날짜>시간대>역할 3중 중첩 — 코드 정본은 "역할∈시간대"(fixed도 synthetic requirement) ◐
- 마감/재오픈이 목록 카드에만, "관리 허브"엔 상태 표시만 ✅
- 캘린더가 "확정 일정"과 "지원 추적" 겸용(색상만 구분) — 전용 지원 내역 화면 부재와 동전의 양면 ✅(정정 반영)

### 패턴 ⑥ 표준은 있는데 다수파가 우회 (design-system drift) — 수치는 메인 세션 재실측

| 표준 | 채택 | 우회 |
|---|---|---|
| `confirmAction()` 확인 다이얼로그 | 6파일 | `Alert.alert` 직접 14파일 — 취소 문구·버튼 순서 제각각 |
| `active:bg-*` (impeccable §21 권장) | 83회 | `active:opacity-*` 169회 — **규칙과 다수파 역전** |
| `<EmptyState>` (compact prop 보유) | 13파일 | "없습니다" 손수 텍스트 55파일 — CTA 없는 빈 상태 다수 |
| `RefreshControl` | 7/23 리스트 | ops 5탭 등 16개 리스트 새로고침 수단 0 (realtime도 없음) |
| `PTR_REFRESH_PROPS` 골드 틴트 | 4파일 | `ConfirmedStaffList.tsx:286` 하드코딩 (WorkLogList는 죽은 코드라 제외) |
| 필수(*) 마커 | — | `FormField` vs `SectionCard` 색·간격 상이(같은 화면 동시 노출) |
| 운영시간 단일 소스 | — | 고객센터 "09:00-18:00" vs 사업자정보 "10:00~18:00" 충돌 ◐ |

## 3. 페르소나 여정 — 아픈 지점만

### 스태프 (홀덤펍 단발 알바)

```
가입(3/3 "완료"…인데 프로필 필수 잔존②) → 홈(탭 밖 화면⑤)
  → 구인구직 탭: 타입 칩 강제 단일선택('전체' 없음) · 검색하면 칩이 죽은 컨트롤⑤
  → 상세 → 지원 → "취소는 마이페이지에서"(존재하지 않는 화면②)
  → 지원 추적: 전용 화면 없음 — 홈 위젯 집계 숫자 or 캘린더 점(색상만 구분)④⑤
  → applied 취소: 상세엔 버튼 없음 — 스케줄 탭 캘린더에서 카드 찾아 시트 열어야③
  → QR 출근: 실패 시 대체 경로 0③ → 근무 완료 → 리뷰 CTA 어디에도 없음, 7일 뒤 조용히 소멸③
  → 과거 이력: "이전 달" 화살표 선형 반복만(완성된 WorkLogList는 죽은 코드①)
```

### 구인자 (홀덤펍 사장 / 대회사 운영팀)

```
공고 작성: 타입 선택(잠금 경고 없음③) · '일반' 카드 라벨이 "지원"② · 5섹션 풀폼 강제
  · 다일차 인원 과소 표시④ · OS 킬 시 작성분 증발(로컬 임시저장 없음③)
  → 등록 성공 → 미리보기 없이 홈②
  → 지원자 관리: 평점 0① · 정원 현황 없음④ · 취소요청 카드는 액션 0(별도 화면 강제)⑤
  → 당일: 출근 현황 수동 새로고침① · 노쇼 오탭=영구③
  → 시간수정: 어느 탭에서 하느냐로 다른 경험⑤
  → 정산: 일괄 실패자 미특정④ → 마감/재오픈: 상세 허브엔 없음(목록으로 복귀)⑤
```

## 5. 기존 실측 감사(같은 날)와의 관계

- **중복 0건** — 확정 24건을 재보고 금지로 주입했고, 실제 위반 없음을 종합 단계에서 재확인.

## 6. 이 감사가 못 본 것

- **실기기 렌더·터치** — 코드 실측만. 다크모드 실렌더·iOS 피커류는 기존 BLOCKING QA 게이트 그대로.
- **실사용 데이터** — 탭 수·이탈률 등 정량 근거 없음. CTA 위계류 판단은 이 때문에 보류.
- **(admin)·ops 내부 UX** — ops는 공통 패턴(RefreshControl 부재)만 포착, 전용 감사 별도.
- **성능** — 프로파일링 없이는 주장하지 않음(에이전트 지시로 원천 차단).
