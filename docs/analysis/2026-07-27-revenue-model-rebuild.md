# UNIQN 수익모델 재설계 분석 (2026-07-27)

> **범위**: 기존 수익모델 문서·결정(`wiki/domain/revenue-model.md`, 과거 지갑/IAP 이력 등)을 **입력에서 배제**하고, 코드베이스에 실제로 구현된 기능 자산과 한국 홀덤 시장 구조만으로 원점 재분석했다.
> **결론 한 줄**: **매칭은 영구 무료, 과금은 "매칭 이후 운영 레이어"에서** — 매장 구독(SaaS) + 긴급충원 종량 + 대회 건당 패스의 3축 하이브리드.

---

## 1. 요약 (Executive Summary)

UNIQN은 겉으로는 구인구직 앱이지만, 코드상 실제 무게중심은 **매칭 이후**에 있다. QR 근태, 급여 자동계산, 주간 근무표, 지점 월정산, 대회 라이브 운영 엔진 — 전부 "사람을 구한 다음"의 기능이며, 이 영역이 경쟁 채널(무료 게시판·카톡 오픈채팅)에 완전히 부재한다.

따라서 수익모델의 핵심 판단은 다음 세 가지다.

1. **매칭 자체에 과금하면 진다.** 대체재가 무료(게시판·오픈채팅)이고, 성사 수수료는 오히려 사용자를 앱 밖(카톡 직거래)으로 밀어내 근태·정산 레이어까지 함께 잃는다.
2. **운영 레이어는 과금해도 이긴다.** 대체 불가(게시판엔 없음)하고, 데이터가 쌓일수록 이탈 비용이 커지며(근무 이력·정산 내역·평판), 지불 주체가 사업자다.
3. **TAM이 작다(홀덤펍 약 2,000개 수준).** 그러므로 수수료율 최적화가 아니라 **매장당 ARPU 확대**가 전략의 축이다 → 단일 요금제가 아닌 구독+종량+이벤트 패스의 스택 구조가 필연.

**목표 수치**: 12개월차 MRR 약 1,000만 원(ARR 1.2억), 24개월차 MRR 약 2,500만 원(ARR 3.0억). 손익분기(월 고정비 500만 원 가정)는 Pro 매장 63곳 시점.

기능 문서가 아니라 스키마·라우트에서 직접 확인한 것만 기재한다.

### 2.1 매칭 마켓플레이스 (공급측 유동성 = 진짜 해자)

| 자산 | 근거 | 과금 관점 |

### 2.3 대회 운영 엔진 (ops) — 별도 상품군

- 등록데스크(`ops_participants`, gap-free 엔트리) / 테이블·좌석 배정 / 블라인드 클럭(서버 앵커) / 상금·바운티 계산(`ops_prizes`) / 스태프 배정(`ops_staff`) / append-only 이벤트 로그(`ops_events`)
- **공개 뷰 2종**: 전광판 `app/(public)/monitor/[token].tsx`, 플레이어뷰 `app/(public)/live/[view_token].tsx` — 비로그인 anon 접근 (`ops_get_monitor_snapshot`, `ops_get_player_view`)
- **공고 연결**: `ops_tournaments.job_posting_id` → 대회 1건이 인력 공고와 묶임. **경쟁사에 없는 유일한 조합**(운영 툴 + 인력 공급)

### 2.4 유입·부가 자산

- 비로그인 공고 목록 `app/(public)/jobs/index.tsx` (웹 유입/SEO 가능)
- 커뮤니티 게시판 5종 `notice / schedule / free / tda / substitute` (`:84-90`)
  → **`substitute`(대타) 게시판의 존재 자체가 "긴급충원" 페인의 코드 증거**다. 유료 상품 가설의 실사용 검증 채널로 쓸 수 있다.
- 원격 구성 `app_config(key, value jsonb)` (`:9712`) → 요금제·가격·플래그를 배포 없이 조정 가능
- 관리자 통계 / ops 퍼널 이벤트(`20260717090500_ops_s1_funnel_events.sql`) → 전환 측정 인프라 존재

## 3. 시장·경쟁 구도

### 3.1 시장 규모 (추정 및 감도)

| 항목 | 값 | 근거·주의 |
|---|---|---|
| 전국 홀덤펍 | 약 2,000개 | 언론 인용치. 단속 국면에 따라 변동 폭이 크므로 ±50% 감도로 다룬다 |
| 유효 타깃(정상 영업 + 외주 인력 수요) | 600~1,000개 | 위의 30~50% 가정 |
| 대회사·시리즈 운영 주체 | 30~80곳 (추정) | 공개 통계 부재 |
| 딜러 시급 | 12,000~15,000원(연습), 경력·서울권 20,000원대 | 정직원 전환 시 월급제 |

**의미**: 홀덤 인력 시장 단독 ARR 상한은 대략 **연 5~7억** 수준이다. 이 천장을 인지하고 설계해야 한다 — "수수료 몇 %"를 다투는 게 무의미한 크기이며, 매장당 지불액을 올리는 상품 스택이 정답이다.

### 3.2 경쟁 지형

| 구분 | 사업자 | 하는 것 | 안 하는 것 (= UNIQN의 공백) |
|---|---|---|---|
| 무료 구인 게시판 | pokerbridge.kr, holdem.kr, holdemdealer.co.kr, holdempubmon.com, 카톡 오픈채팅 | 공고 나열 | 지원자 관리·근태·정산·평판 **전무** |
| 매장 운영 SaaS | 스마트홀덤 (예약·타이머·회원관리·정산·**딜러 스케줄**) | 매장 내부 운영 | **외부 인력 공급(마켓플레이스) 없음** |
| 대회/이용권 플랫폼 | 와홀덤 (이용권·참가권 디지털 발급, QR 바이인, 정산, 실명회원 1.3만+) | 대회 참가자 측 | 스태프 수급 없음 · **돈 흐름 관여로 규제 노출** |
| 종합 알바 플랫폼 | 알바몬·알바천국 | 대량 트래픽, 유료공고 1.3만~19.8만 원/일 | 홀덤 도메인 이해·근태·정산 없음 |

**포지셔닝 결론**:
> 게시판은 **공급은 있으나 운영이 없고**, 스마트홀덤류는 **운영은 있으나 공급이 없다**. UNIQN만 `공급(스태프 풀+평판) → 배치 → 근태 → 정산`을 **하나의 파이프라인**으로 갖는다. 수익모델은 반드시 이 파이프라인의 하류(운영)에서 걷어야 한다. 상류(매칭)에 과금하면 파이프라인 자체가 끊긴다.

또한 와홀덤이 QR 바이인·참가권 발급으로 **돈 흐름에 직접 관여**하는 것과 달리, UNIQN이 그 영역을 비워두는 것은 손실이 아니라 **규제 차별화**로 포지셔닝 가능하다(§6.1).

## 4. 과금 후보 평가 — 왜 채택/기각인가

| 후보 | 판정 | 사유 |
|---|---|---|
| **매장 운영 구독(SaaS)** | ✅ **핵심** | 대체재 없음 · 데이터 락인 · 사업자 지불 · 예측 가능한 MRR |
| **긴급충원 종량 부스트** | ✅ **핵심** | 지불의사가 가장 뾰족한 순간(당일 노쇼) · `urgent_config` 스키마 기구현 · 무료 사용자도 과금 접점 |
| **대회 건당 이벤트 패스** | ✅ **핵심** | 대회사는 D-7~D-day 집중형 → 상시 구독이 부적합, 건당이 수요 형태와 일치 |
| 인증 딜러 배지 / 프리미엄 인재풀 | 🟡 후행 | `bubble_score` 축적 후. 구인자 과금(구직자 아님) 형태로만 |
| 전광판 스폰서 슬롯 | 🟡 후행 | 공개 monitor 뷰의 관중 트래픽. 대회 규모 확보 후 |
| 임금 시세 리포트 (익명 집계) | 🟡 마케팅 우선 | 초기엔 **무료 공개**로 유입/권위 확보, 유료화는 나중 |
| **성사당 매칭 수수료** | ❌ 기각 | (a) 카톡 직거래 이탈 유발 → 근태·정산 레이어까지 상실 (b) 무료 게시판 대체재로 가격 탄력성 높음 (c) 직업소개 요금 규제 접점 |
| **구직자(스태프) 과금** | ❌ 기각 | 규제 리스크 + 공급측 유동성이 이 마켓플레이스의 병목. 공급을 깎는 과금은 자해 |
| **바이인·상금 결제 수수료** | ❌ 기각 | 관광진흥법 카지노 유사행위 리스크(§6.1). 한국 홀덤 맥락에서 가장 위험한 모델 |
| 앱 내 IAP | ❌ 기각 | B2B 과금은 웹 결제로 → 스토어 수수료 30% 회피 |

## 5. 권장 수익모델: 3축 하이브리드

> ⚠️ **이 절의 요금표는 초안이다.** 확정 설계는 `2026-07-27-operations-billing-design.md`를 따른다 —
> 단순화 결정으로 **무료 사용량 한도(월 30건)·좌석 추가 과금·크레딧 묶음·다지점 할인은 전부 폐기**됐고,
> 가격도 매장 운영 월 50,000원 / 긴급공고 10,000원 / 대회 100,000원으로 조정됐다.

```
[0층] 무료 — 매칭 전량 개방 (유동성 엔진, 영구 무료)
   └ 공고 등록 무제한 · 지원자 관리 · 채팅/연락 · 기본 평판 열람
        ↓ (사람을 구한 다음)
[1축] 매장 Pro 구독 ─ 월 59,000원 / 지점       ← MRR 기반
[2축] 긴급 부스트   ─ 건당 9,900원 (10건 79,000원)  ← 종량, 무료 사용자 포함
[3축] 대회 패스     ─ 건당 99,000원 / 시리즈 월 290,000원 ← 대회사 전용
        ↓ (후행)
[4층] 인증 배지 · 전광판 스폰서 · 데이터 리포트
```

### 5.1 무료 티어 (경계 설계)

**원칙: 이미 무료로 쓰던 기능을 뺏지 않는다.** v1.0.5가 이미 배포 중이므로 기존 워크스페이스는 **grandfathering**(기존 한도 영구 보존) 처리한다. 유료화는 "볼륨 초과분"과 "신규 기능"에만 건다.

| 항목 | 무료 | Pro |
|---|---|---|
| 공고 등록·지원자 관리 | 무제한 | 무제한 |
| QR 근태 기록 | **월 30건**까지 | 무제한 |
| 정산 계산·상세 | 기본(건별) | 무제한 + 월 단위 |
| 지점 월정산 / 역할별 단가표 | ✕ | ✅ |
| 주간 근무표(weekly-grid) | 읽기 전용 | 편집·자동배치 |
| 워크스페이스 멤버 | 2석 | 5석 (추가 1석 9,900원) |
| 정산 내보내기(CSV/PDF) | ✕ | ✅ |
| 평판·노쇼 이력 상세 | 요약 | 전체 이력 |

> 월 30건 = 딜러 3명 × 주 2~3회 규모. **가장 작은 매장은 계속 무료로 남되, 정상 영업 매장은 자연히 초과**하도록 설정한 값. 초기 3개월 실측 후 `app_config`로 조정한다.

### 5.2 가격 근거

| 가격 | 앵커 |
|---|---|
| Pro 59,000원/월 | 알바몬 유료공고 **1.3만 원/일** → 월 5건만 올려도 6.5만 원 초과. 홀덤펍 월 인건비(딜러 5명 × 200만 ≈ 1,000만) 대비 **0.6%** → 심리적 저항선 아래. 연납 590,000원(2개월 무료) |
| 부스트 9,900원 | 당일 딜러 1명 공백의 실손실(영업 차질 + 대체 수배 인건 시간) 대비 1시간 시급 미만. 즉시 결제 저항 최소 구간 |
| 대회 패스 99,000원 | 대회 1건 총예산(장소·상금·인건) 대비 1% 미만. 운영 툴 단독으론 무료가 표준이므로 **"운영 엔진 + 스태프 수급 + 전광판/플레이어뷰"를 묶은 값**으로만 정당화됨 |

### 5.3 각 축 상세

**[1축] 매장 Pro** — 지점(venue) 단위 구독. 다지점 운영자는 지점당 과금하되 3지점 이상 20% 체감. 과금 주체는 `workspace`(스키마상 이미 경계 확정).

**[2축] 긴급 부스트** — `posting_type='urgent'` 공고에 붙는 소진형 크레딧. 제공 가치:
- 목록 상단 고정(24h) + 긴급 뱃지
- 조건 부합 스태프(지역·역할·최근 근무 이력·bubble_score 기준)에게 **타겟 푸시 발송**
- 미충원 시 **자동 환불**(크레딧 복원) — 성과 보증이 전환율을 크게 올린다
- `substitute` 게시판에 자동 교차 게시

**[3축] 대회 패스** — `ops_tournaments` 생성 시 엔타이틀먼트 검사. 포함: 등록데스크·좌석·클럭·상금 계산·전광판·플레이어뷰·스태프 배정·대회 전용 공고. 시리즈 패스는 월 무제한 대회 개최.

## 6. 제약 조건 (설계 시 반드시 준수)

### 6.1 법·규제

| 제약 | 내용 | 설계 반영 |
|---|---|---|
| **관광진흥법 카지노 유사행위** (2024-02-27 시행) | 비카지노 사업자의 영리 목적 홀덤 제공으로 재산상 이익·손실 발생 시 처벌. 2024년 이후 전국 집중단속 지속 | **바이인 결제·참가권 발급·상금 지급 레일에 구조적 비관여.** `ops_prizes`는 금액 계산·표시만(현행 코드 그대로 유지) |
| **직업안정법 / 직업정보제공사업** | 구인·구직 정보 제공은 고용노동부 **신고 대상**. 신고번호를 매체에 표시해야 하며, "취업추천·취업지원" 등 표현 사용 제한. 구직자 요금 징수는 유료직업소개(등록제) 영역으로 별도 규제 | **구직자 과금 0원 유지.** 직업정보제공사업 신고 필요 여부를 노무·법률 검토로 확정하고, 필요 시 신고번호를 앱 하단·웹에 표시 |
| **앱스토어 IAP** | 앱 내 디지털 재화 결제는 스토어 수수료 대상 | 모든 유료 결제는 **웹 전용**(Cloudflare Pages `functions/`). 앱에서는 결제 UI·유도 문구 미노출, 상태 표시만 |

### 6.2 사업 제약

- **TAM 천장(연 5~7억)** → 3년 내 인접 시장 확장 축을 병행 준비(§8)
- **단속 리스크** → 매장 폐업이 곧 이탈. 대회사·정식 대회 비중을 의도적으로 키워 헤지
- **경쟁사 선점** → 스마트홀덤류가 "딜러 스케줄"을 이미 보유. 우리 차별점은 **외부 인력 공급**이므로, 세일즈 메시지는 "운영 툴"이 아니라 **"사람이 오는 운영 툴"**이어야 한다

## 7. 단위경제 및 시뮬레이션

### 7.1 기본 시나리오 (유효 매장 700곳 가정)

| 항목 | 12개월차 | 24개월차 |
|---|---|---|
| Pro 매장 수 (전환율) | 105곳 (15%) | 250곳 (36%) |
| Pro 매출 | 6,195,000원 | 14,750,000원 |
| 부스트 (건×9,900) | 250건 = 2,475,000원 | 600건 = 5,940,000원 |
| 대회 패스 | 15건 = 1,485,000원 | 30건 + 시리즈 5 = 4,420,000원 |
| **MRR** | **약 1,015만 원** | **약 2,511만 원** |
| **ARR 환산** | **약 1.2억 원** | **약 3.0억 원** |

### 7.2 감도 분석 (24개월차 MRR)

| 시나리오 | 유효 매장 | Pro 전환 | MRR |
|---|---|---|---|
| 비관 (단속 심화) | 350 | 20% | 약 1,000만 원 |
| 기본 | 700 | 36% | 약 2,500만 원 |
| 낙관 (시장 정상화) | 1,000 | 40% | 약 4,200만 원 |

### 7.3 LTV / CAC

- 유료 매장 ARPU: Pro 59,000 + 부스트 평균 2건(19,800) ≈ **월 78,800원**
- 월 이탈률 3% 가정 → 평균 수명 33개월 → **LTV ≈ 208만 원**(마진 80% 반영)
- CAC: 직접 영업(매장 방문·오픈채팅·대회 현장) 기준 **10~30만 원/매장** 추정
- **LTV/CAC ≈ 7~20** → 건전. 초기엔 유료 광고보다 **직접 영업 + 대회 현장 접점**이 압도적으로 효율적
- **손익분기**: 월 고정비 500만 원(1인 개발·운영 + 인프라 + PG) 가정 시 **Pro 63곳 / MRR 500만 원** — 기본 시나리오상 12개월차 이전 도달

## 8. 확장 축 (TAM 천장 대응)

1. **인접 단발 인력 시장** — 근태·정산 엔진은 홀덤 비특화다. 전시·행사·이벤트 스태프, 매장 단기 알바 등으로 **동일 엔진 재활용** 가능. 도메인 특화 부분은 `StaffRole`과 ops뿐. 단속 리스크의 최선 헤지.
2. **대회 생태계 상류** — 플레이어 포털(가입·클레임·전적) → 랭킹/포인트 → 전국 대회 캘린더. 관중·참가자 트래픽 확보 시 전광판 스폰서·대회사 리드 상품이 열린다. **단, 참가권·상금 흐름은 절대 미진입**(§6.1).
3. **데이터 상품** — `work_logs` 익명 집계 기반 "홀덤펍 임금 시세 리포트". 초기 무료 공개로 SEO·권위 확보 후 유료 전환 검토.

## 9. 구현 로드맵

### Phase 0 — 계측 (0~4주, 코드 변경 최소)

과금 설계는 실측 없이 확정하지 않는다.

- 워크스페이스별 **월 QR 근태 건수 분포** 집계 → 무료 한도(30건) 검증
- `posting_type='urgent'` 사용 빈도 + `substitute` 게시판 활동량 → 부스트 수요 검증
- `venue-settlements` / `weekly-grid` 화면 진입율 → Pro 기능 후보 우선순위
- 대회 개최 건수·`ops_tournaments` 생성 추이 → 대회 패스 수요
- 계측 인프라: 기존 퍼널 이벤트(`20260717090500_ops_s1_funnel_events.sql`) 패턴 재사용

### Phase 1 — 엔타이틀먼트 기반 (4~8주)

결제보다 **권한 게이트가 먼저**다. 이게 있어야 요금제를 코드 배포 없이 바꿀 수 있다.

```sql
-- 신규 테이블 (초안)
billing_plans(key, name, price_krw, limits jsonb, features text[])
workspace_subscriptions(workspace_id, plan_key, status, current_period_end, grandfathered_limits jsonb)
boost_credits(workspace_id, balance, ...)  -- 소진형
entitlement_ledger(workspace_id, feature, granted_by, expires_at)  -- 대회 패스 등 단건
```

- **SECDEF 함수** `has_entitlement(workspace_id, feature)` 신설 → RLS 정책·쓰기 RPC에서 일괄 검사 (CLAUDE.md의 "다중 쓰기 = RPC 필수" 규칙과 정합)
- 요금제·가격·한도는 `app_config` + `billing_plans`로 원격 조정
- **grandfathering 필드 필수** — 기존 사용자 한도 보존

### Phase 2 — 웹 결제 (8~12주)

- **PortOne 정기결제(빌링키)** — 본인인증으로 이미 연동된 벤더라 통합 비용이 낮다
- 결제 페이지는 **웹 전용**(`functions/` Cloudflare Pages Functions, `console.log` 허용 예외 구역)
- 앱은 구독 상태 **표시만**, 결제 유도 문구·링크 미노출 (스토어 정책)
- 세금계산서 발행(사업자 대상 필수)

### Phase 3 — 상품 순차 출시

| 순서 | 상품 | 이유 |
|---|---|---|
| 1 | **긴급 부스트** | 스키마 기구현 · 단건 결제라 구독 인프라 완성 전 출시 가능 · 지불의사 검증에 최적 |
| 2 | **매장 Pro** | 부스트 결제 경험으로 신뢰 확보 후 구독 제안 |
| 3 | **대회 패스** | 대회 시즌에 맞춰 타이밍 |
| 4 | 인증 배지 · 스폰서 | 데이터·트래픽 축적 후 |

### Phase 4 — 최적화

- 무료 한도 재조정(실측 기반), 연납 전환 캠페인, 다지점 번들, 이탈 예측·리텐션

## 10. 반론과 대응

| 반론 | 대응 |
|---|---|
| "매칭 수수료가 더 크지 않나?" | 성사당 5,000원 × 월 2,000건이라도 1,000만 원인데, **성사 신고 자체를 회피**(카톡 직거래)당한다. 구독은 회피 불가능하고 예측 가능하다 |
| "무료 게시판이 있는데 누가 돈을 내나" | 게시판은 **공고 나열까지만** 한다. 과금 대상은 근태·정산·근무표로, 게시판이 제공하지 않는 영역이다. 애초에 경쟁 상품이 다르다 |
| "스마트홀덤이 이미 딜러 스케줄을 한다" | 그들은 **내부 인력의 스케줄**만 짠다. 사람이 없을 때 사람을 데려오지 못한다. 우리의 세일즈 한 문장: **"사람이 오는 운영 툴"** |
| "대회 참가비 수수료가 가장 큰 돈 아닌가" | 맞지만 한국에선 **가장 위험한 모델**이다(§6.1). 소프트웨어 제공자도 방조 리스크에 노출된다. 성장률과 존속을 맞바꾸지 않는다 |
| "TAM 5~7억이면 사업이 되나" | 1~3인 규모라면 충분히 성립하고, 인접 시장 확장(§8)이 실질 상한을 결정한다. 이 천장을 알고 시작하는 것과 모르고 시작하는 것은 다르다 |

## 11. 즉시 실행 항목

1. **Phase 0 계측 쿼리 작성·실행** — 무료 한도(월 30건)와 부스트 수요를 데이터로 확정. 가격표는 그 다음이다.
2. **직업정보제공사업 신고 필요 여부 노무·법률 검토** — 유료화 전 반드시 선행. 신고 시 신고번호 표시 UI 필요.
3. **`substitute` 게시판을 부스트 MVP로 활용** — 결제 붙이기 전에, 긴급 공고에 푸시 발송을 수동으로 붙여 충원 성공률을 측정한다. 유료화 가치의 사전 증명.
4. **grandfathering 정책 문서화** — v1.0.5 기존 사용자 보호 범위를 유료화 착수 전에 확정.
