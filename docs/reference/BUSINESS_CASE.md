# 비즈니스 케이스

최종 업데이트: 2026-03-30  
기준 코드: `uniqn-mobile/app/`, `uniqn-mobile/src/services/`, `uniqn-mobile/src/repositories/`, `functions/src/`

이 문서는 현재 코드가 실제로 지원하는 제품 범위와 운영 가치를 요약합니다.

## 현재 제품이 해결하는 문제

UNIQN은 현재 코드 기준으로 다음 운영 흐름을 하나의 모바일 앱과 Firebase 백엔드 안에서 처리합니다.

- 구인 공고 작성과 관리
- 지원 접수, 승인, 거절, 배정 관리
- QR 기반 출퇴근과 근무 기록 관리
- 정산 확인과 근무 이력 조회
- 공지, 문의, 신고 운영
- 관리자 승인, 통계, 사용자 관리

## 현재 주요 사용자

- `staff`: 공고 탐색, 지원, 일정 확인, 알림 수신, 근무 기록 확인
- `employer`: 공고 작성, 지원자 관리, 정산과 운영 상태 확인
- `admin`: 승인, 신고, 문의, 공지, 통계, 사용자 관리

## 현재 코드가 제공하는 운영 가치

### 운영 속도 향상

- 공고, 지원, 일정, 알림 흐름이 모바일 앱 안에서 이어집니다.

### 운영 통제 강화

- 관리자 라우트에서 승인, 신고, 문의, 공지, 통계를 직접 관리합니다.

### 현장 사용성

- QR 출퇴근, 일정 캘린더, 푸시 알림, 생체 인증 같은 모바일 중심 흐름이 포함됩니다.

### 데이터 일관성

- `Repository -> Service -> Hook` 흐름과 Query key 관리로 데이터 접근 경로를 통일합니다.

## 현재 출시 범위에서 제외하는 것

- 런타임 코드에 없는 결제와 포인트 시스템
- 구독 SDK 연동을 전제로 한 수익화 구현
- 과거 설계 문서의 미구현 KPI, 매출 추정, ROI 수치

## 후속 검토 항목

1. 실제 결제와 포인트 시스템을 출시 범위에 넣을지 별도 결정합니다.
2. 관리자 통계와 운영 리포트를 어떤 KPI로 제품화할지 정리합니다.
3. 신고와 문의 데이터를 운영 지표로 어떻게 연결할지 정의합니다.
