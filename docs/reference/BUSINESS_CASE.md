# 비즈니스 케이스

**최종 업데이트**: 2026년 3월 14일
**상태**: 현재 제품 범위 기준

이 문서는 현재 코드에 실제로 보이는 제품 범위를 바탕으로 작성합니다. 아직 코드에 없는 결제/구독 기능이나 과거 웹 성능 수치를 현재 출시 기능처럼 다루지 않습니다.

## 현재 제품이 해결하는 문제

현재 코드 기준으로 UNIQN은 다음 운영 문제를 줄이는 데 초점을 둡니다.

- 구인공고 작성과 관리
- 지원서 확인과 확정
- 일정/출퇴근/QR 기반 근무 관리
- 정산 및 근무 이력 확인
- 공지, 신고, 문의 운영
- 관리자 승인 및 사용자 관리

## 주요 사용자

- `staff`: 공고 탐색, 지원, 일정 확인, 알림 수신, 고객지원 이용
- `employer`: 공고 작성, 지원자 관리, 정산/운영 확인
- `admin`: 승인, 신고, 문의, 공지, 통계 관리

## 현재 코드가 뒷받침하는 가치 제안

### 운영 속도 향상

- 모바일 앱에서 공고, 지원, 일정, 알림 흐름을 한 번에 처리합니다.

### 운영 통제 강화

- 관리자 라우트에서 승인/신고/문의/공지/통계를 직접 관리합니다.

### 현장 사용성

- QR 출퇴근, 일정 캘린더, 모바일 알림, 다크 모드, 생체 인증 같은 모바일 기능이 들어 있습니다.

### 데이터 일관성

- Repository 패턴과 Query Key 중앙 관리로 데이터 접근 경로를 통일합니다.

## 현재 코드 기준 사업화 메모

- 앱은 역할 기반 운영 도구로서의 핵심 흐름을 이미 갖추고 있습니다.
- 다만 유료 포인트, 앱 내 결제, 외부 구독 SDK 연동은 현재 저장소의 런타임 구현 근거가 부족합니다.
- 따라서 수익화 문서는 "구현 완료"가 아니라 "추가 설계 또는 향후 작업"으로 다뤄야 합니다.

## 향후 검토 항목

- 결제/수익화 기능을 실제 코드에 도입할지
- 운영 리포트와 관리자 통계를 어떤 KPI로 연결할지
- 고객지원/신고 데이터로 운영 품질 지표를 만들지

## 문서 원칙

이 문서에는 아래 내용을 현재 사실처럼 적지 않습니다.

- 구현되지 않은 결제 플랫폼 연동
- 현재 코드에 없는 글로벌 번역 런타임

- 근거 없는 시장 점유율, ROI, 매출 수치
