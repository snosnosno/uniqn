## 2. 세션 분할 — 순서 엄수

앞 세션이 끝나야 다음이 성립한다. 한 세션에 두 개를 묶지 말 것.

### S1. 공고 상세 진입점 12 → 3

**목표**: 공고 상세에 `지원자` · `근무` · `공고 수정` 세 타일과 `공유` · `⋯`만 남는다.

- 타일에서 제거 → 흡수처
  - `취소 요청 관리` → [근무] 줄의 상태 + 승인/거절/전화 버튼
  - `스태프 관리/정산` → **[근무]로 개명**하고 날짜별 그룹 유지
  - `스태프 공지` → [근무] 헤더의 `메시지`
  - `지원 QR` → `공유` 시트 안으로 (링크 · QR · 구직자 화면 보기)
  - `함께 관리할 사람` → `⋯` 안으로
  - `미리보기`(헤더 눈 아이콘) → 삭제. 공고 작성 마지막 단계로 옮긴다
  - `라이브 운영` → **그대로 둔다** (대회일 때만 뜨는 조건부라 평소엔 없다)
- 배지는 **합치지 않는다**. `3명 대기` / `취소요청 1` 각각 유지 —
  `할 일 6` 처럼 뭉치면 눌러봐야 안다
- 이름은 대상 기준으로: `스태프 관리/정산` → `근무`. "관리"로 끝나는 타일이 3개라 구분이 안 됐다

**검증**: `app/(employer)/my-postings/__tests__/` 의 기존 스위트 + 진입점 개수 단언 신설.
`npm run quality` · 영향권 jest.

### S2. 정산 워크플로우 제거 (UI 계층)

**목표**: 구인자 화면에서 `지급 대기 / 지급 완료` 상태가 사라지고 **금액만** 보인다.

- [근무] 화면
  - 퇴근이 찍힌 줄에만 금액을 붙인다. **안 찍힌 줄에 추정 금액을 만들지 않는다** —
    `퇴근을 찍어야 금액이 정해져요`
  - 맨 위 한 줄 `지급 예정 합계 474,000원 ›` → 누르면 **사람별 합산** 시트
    (민수의 3일치가 한 줄이어야 세 번 보내지 않는다)
  - `계산 근거` 시트: 출근·퇴근·인정 근무·시급·합계 + **변경 이력**
- 제거: 공고별 정산 화면(`my-postings/[id]/settlements.tsx`의 정산 탭) ·
  지점 정산 화면(`venue-settlements.tsx`) · 일괄 지급 · 지급 완료 버튼
- **구직자 쪽(§3)**: 라벨만 정리. 구조는 건드리지 않는다
- 컬럼·RPC·트리거·pgTAP는 **손대지 않는다**

**검증**: 금액 계산 결과가 기존 정산 화면과 동일한지 회귀 테스트.
구직자 화면에 `지급 대기` 문구가 남지 않는지 Grep(`e2e/`도 별도 확인 — eslint 사각지대).

### S3. 내 공고 탭 세그먼트 + 오늘 한 줄

**목표**: 탭 안에서 `[공고] / [근무표]` 전환. 오늘 신호는 **있을 때만** 맨 위 한 줄.

- 세그먼트 기본값은 **[공고]** — 신규 사용자 경험을 바꾸지 않는다
- 오늘 스트립: 미출근 · 퇴근 미기록 (0건이면 렌더하지 않음).
  누르면 오늘 상세로. 데이터는 기존 셀렉터 재사용 —
  `TodayOpsStrip` 계열 · `summarizeMissingCheckouts` · `useVenueMissingCheckouts` ·
  `selectPostingCapacityGaps`
- ⋯ 로 이동: 묶음 공유 · 받은 초대
- 팀 링크: **멤버 2명 이상일 때만** 노출

**검증**: 세그먼트 전환 + 오늘 스트립 0건 미렌더 단언.

### S4. 근무표 밀도 정리 + 출처 표시

- 사람 줄에 **출처 공고 칩** (`토요일 딜러 4명 공고에서`) — 컨테이너 직속 배치는 `직접 배치`
  🔑 이게 없어서 "공고는 근무표를 채우는 도구"가 화면에서 성립하지 않았다
- 칩 3개 + 입력칸 + 저장 버튼 → `3/5명 · 2명 부족` 한 줄, 숫자 탭하면 편집
  ⚠️ **PR #490에서 고친 수동/파생 분리를 깨지 말 것** — 입력칸은 `manualTarget`만 다룬다
- 지점·팀 선택기: 2개 이상일 때만
- `GridBadgeLegend` 제거 검토 (뱃지를 자명하게)

### S5. 팀·협업자 구분 문구

- 팀 화면 상단: `이 팀의 모든 공고를 함께 봅니다`
- 협업자 화면 상단: `이 공고 하나만 함께 봅니다` + 팀으로 가는 링크
- 멤버가 본인뿐이면 팀 진입점 미노출

## 3. 내 스케줄 탭(구직자)에서 불가피한 변경

사용자 지시는 **"내 스케줄 탭은 건드리지 말자"**였고 구조는 지킨다.
다만 정산 상태를 없애면 구직자가 영원히 `지급 대기`를 보게 되므로 **라벨만** 고친다.

| 파일 | 지금 | 바꿀 것 |
|---|---|---|
| `src/components/schedule/tabs/SettlementTab.tsx` | 지급 대기 / 지급 완료 배지 | 금액 + 변경 이력 |
| `src/components/schedule/ScheduleCard.tsx` | 정산 상태 표시 | 금액만 |
| `src/components/schedule/tabs/InfoTab.tsx` | 정산 상태 참조 | 동일 |
| `src/hooks/useSettlement.ts` | 상태 변이 훅 | 읽기만 쓰도록 호출부 정리 |

**구직자 문구 원칙**: `입금은 사장님이 직접 보냅니다` · `금액이 다르면 사장님께 문의하세요`.
앱이 지급을 보증하는 것처럼 읽히면 안 된다.

## 4. 사용자 결정 (2026-09-14 확정 — 재논의 금지)

1. **상시(fixed) 공고 [근무]** → 안내문 + 근무표 링크. (S1 에 반영 완료)
2. **대회 하나 = 공고 하나에 여러 직무** → 묶음 단위는 **공고**.
3. **세그먼트 범위** → 기준은 **'나'**, 지점은 **필터**. 지점이 1곳이면 필터를 숨긴다(0/1개 규칙).
4. **출퇴근 QR 지점당 1장 / 구인자가 스태프 QR 스캔** → 사용자가 "더 고민" → **보류. 건드리지 말 것.**
   (참고: 페이로드가 `{type:'venue', jobPostingId}`(`src/services/work/eventQRService.ts:175`)라 UI 변경이 아니다)

### 슬라이스별 결정

- **S1**
  - 헤더 출퇴근 QR 버튼은 **유지**한다.
  - 취소 요청은 [근무] 상단 한 줄(`CancellationRequestsBanner`, 0건이면 미렌더)까지만 한다.
  - **사람 줄 단위 승인/거절 = S1b 로 분리**한다.
- **S2**
  - PR 을 **S2a(구인자) / S2b(구직자)** 로 나눈다.
  - 지점 정산 화면은 읽기 전용 `지점 근무 금액` 으로 둔다.
  - 과거 지급완료 행에는 **동결 금액**을 표시한다. 단 `지급 예정 합계`에서는 **빼고** 따로 밝힌다.
  - 구직자 화면
    - `미지급` 필터를 제거한다.
    - 대시보드는 `이번 달 근무 금액` 한 칸으로 줄인다.

### 7.4 되돌리면 안 되는 규칙 (웨이브 누적)

- 진입점을 신호에 따라 숨기지 않는다. 조건부 숨김은 **0개일 때만** 한다. 승격 카드가 떠도 타일 목록에서 빼지 않는다.
- 배지는 합치지 않는다.
- 앱은 돈을 보내지 않는다.
  - `지급 예정` 에 과거 지급완료 금액을 넣지 않는다.
  - 지급을 보증하는 문구를 쓰지 않는다.
- DB 컬럼·RPC·트리거·pgTAP 는 이 웨이브에서 손대지 않는다.
- testID `job-posting-manage-settlements` 등 e2e 호환용 testID 는 유지한다.
- `accessible` + 명시 `accessibilityLabel` 컨테이너에 안내 문구를 넣으면 **라벨에도 넣는다**(자식 Text 는 낭독되지 않는다).
