2. **사용자 관점 설명** — 아래 구조로, 기술 배경 없는 사장님에게 말하듯 먼저 요약하고 상세는 뒤에:
   - **공고 카드**: 복지 줄 다음에 모집 조건(복장·경력) 줄이 생겼다 — 언제 보이고 언제 안 보이나
   - **급여**: '모든 역할 동일 급여'가 기본 해제로 바뀌었다 — 역할 고르면 딜러 2만/플로어 3만/기타 2만이 자동으로 채워지고(기본값 배지), 역할별 스테퍼·금액 탭 직접입력이 생겼다. defaultSalary가 최저값으로 기록되는 이유(카드 표시·정산 폴백)도 짧게
   - **일정**: 날짜 여러 개 고르면 3지 선택(모든 날짜 같은 조건 / 연속 날짜 묶음 지원 / 날짜마다 따로)이 뜬다 — 각각 지원자에게 어떻게 보이는지(특히 '묶음 지원'만 범위 일괄 지원), 그룹 2개+ 화면(헤더 재편집·삭제 되돌리기·+ 일정 추가)
3. **리뷰가 잡아낸 것 설명** (신뢰 근거): fable 리뷰 3회 — S2 H-1(고아 급여 엔트리가 카드/정산에 과소 공시될 뻔) · S1 H-1(되돌리기 버튼이 실제로는 안 그려지고 있던 false-green — Toast 렌더러 배선으로 해소) · 세그먼트 클램프 등. "테스트가 있는데 왜 리뷰가 필요했나"의 실례로.
