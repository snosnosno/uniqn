## 0. 결론 요약

- **토큰 타입 신설 없음** — 기존 시 slug(`부산`, `경기 수원시`)를 "시 전체" 토큰으로 오버로드. 확장 규칙만 3층화하면 기존 저장 필터(MMKV persist)가 자동으로 새 의미(시 전체 = 시 + 소속 구)로 승격되고, 이는 구 도입 전 매칭 동작과 정확히 일치(무회귀).
- **slug 추가만, 기존 67개 불변** — 신규 ~200 slug(도 시·군 + 구). DB 변경 0, 마이그레이션 0.
- **UI**: 좌측 9탭(8권역+기타), 우측 시 칩 그리드 + 구 인라인 확장(단일 아코디언). 좌측 `w-24`→`w-[72px]` 축소 + 광역시 라벨 축약("부산광역시"→"부산").

## 2. 데이터 모델 (`src/constants/regions.ts`)

### 2-1. 그룹 개편

```ts
export type RegionGroup =
  | '서울' | '경기' | '인천' | '강원' | '충청' | '전라' | '경상' | '제주' | '기타';
```

- '광역시' 그룹 폐지: 부산·대구·울산→경상, 광주→전라, 대전·세종→충청, 인천→인천(단독).
- **persist 호환**: 그룹 토큰은 `GROUP_ALL_SUPPORTED`였던 서울/경기/제주 3종만 저장 가능했고 셋 다 유지 → 기존 `group:*` 토큰 전부 유효. slug 토큰은 slug 불변이라 전부 유효. `sanitizeRegionTokens`가 만약의 잔재를 무손실 정화.

### 2-2. slug 명명 규칙 (기존 패턴 연장)

| 레벨 | 패턴 | 예 |
|---|---|---|
| 광역시 구 | `{광역시slug} {구명}` | `부산 해운대구`, `인천 부평구`, `대구 수성구` |
| 도 시·군 | `{도약칭} {시군명}` | `강원 원주시`, `충북 청주시`, `경남 김해시` |
| 일반구 | `{시slug} {구명}` | `경기 수원시 장안구`, `충북 청주시 서원구` |

- 도약칭 = 강원/충북/충남/전북/전남/경북/경남 (특별자치도 명칭 무관 — slug는 UI 비노출 식별자).
- 군은 시와 동급 2레벨(경기 가평군 선례). 구 미만(읍면동) 없음.

### 2-3. RegionOption 확장

```ts
export interface RegionOption {
  slug: string;
  label: string;        // 구/시군명. 광역시는 축약("부산") ← 기존 "부산광역시"에서 변경(표시 전용)
  group: RegionGroup;
  keyword: string;
  subGroup?: string;    // 우측 패널 소섹션 (아래 표)
  parentSlug?: string;  // 구 레벨 전용 — 소속 시 slug. 시·군 레벨은 없음
}
```

| 그룹 | subGroup |
|---|---|
| 서울 | 없음 (25구 flat — 현행 유지) |
| 경기 | 남부/북부 (현행 유지, 신규 일반구는 parentSlug로만 연결) |
| 인천 | 없음 (구 8~10개 flat — 서울과 동일 취급, `인천` 시 칩 없이 [인천 전체]=group 토큰) |
| 강원 | 없음 |
| 충청 | 대전·세종 / 충북 / 충남 |
| 전라 | 광주 / 전북 / 전남 |
| 경상 | 부산·대구·울산 / 경북 / 경남 |
| 제주 | 없음 (현행 유지) |

- **주의(기존 렌더러 계약)**: subGroup이 하나라도 있는 그룹은 전 항목에 subGroup 필수(없으면 렌더에서 증발). 혼합 그룹은 광역시에도 subGroup 부여.
- **인천 특례**: 기존 `인천` slug(시 단위)는 존재하나 UI 시 칩으로 노출하지 않음 — "인천 전체"는 `group:인천` 토큰. `인천` slug 토큰은 저장 호환용으로만 유효(라벨 "인천").
- 파생 맵 신설: `getRegionChildren(slug): RegionOption[]` / `hasRegionChildren(slug): boolean` (`CHILDREN_BY_PARENT` 맵).
- 정렬: 광역시(고정 순) → 도 내 시 가나다 → 군 가나다. 서울·경기·제주 기존 순서 불변.

## 3. 선택 모델 (`src/utils/regionSelection.ts`)

### 3-1. 확장 규칙 (`expandRegionTokens`)

| 토큰 | 확장 결과 |
|---|---|
| `group:경상` | 그룹 내 전 slug (시+구 전부) |
| `부산` (구 보유 시) | `부산` + 소속 구 16개 — **시 전체 의미** |
| `부산 해운대구` (구) | `부산 해운대구` + `부산` — **결정③ 부모 포함** |
| `강원 원주시` (구 없는 시) | 자기 자신만 |

### 3-2. 상호배타 3층 (`toggleRegionToken`)

- 그룹 토큰 추가 → 같은 그룹의 시/구 토큰 전부 해제 (기존).
- 시/구 slug 추가 → 같은 그룹의 그룹 토큰 해제 (기존).
- **신규**: 시 slug 추가 → 그 시의 구 토큰 해제. 구 slug 추가 → 부모 시 토큰 해제.
- `MAX_REGION_UNITS = 5` 유지 (그룹·시 토큰도 1단위).

### 3-3. 라벨

- `regionTokenLabel`: 구 보유 시 토큰은 `"부산 전체"` / `"수원시 전체"` (전체 의미 명시). 그 외 기존과 동일.

## 4. UI (`RegionFilterSheet.tsx`)

- **좌측 탭**: `w-24`→`w-[76px]`(구현 확정 — 2글자 라벨+배지+웹 스크롤바까지 줄바꿈 없는 최소 폭 실측), 9탭 + 선택수 배지. 세로 스크롤 유지. ⚠️RN-web ScrollView 는 기본 flexGrow:1 이라 `grow-0 shrink-0` 필수(없으면 50/50 분할 — 실측 버그).
- **우측 패널**(subGroup 섹션 구조 유지):
  - 그룹 전체 행: `GROUP_ALL_SUPPORTED` = 기타 제외 전 그룹으로 확대.
  - 시-레벨 칩 그리드(2열 48%): 구 없는 시 = 기존 토글 칩. **구 보유 시 = 확장 칩**(라벨+▸/▾+하위선택수 배지, 탭=펼침 토글, `accessibilityState.expanded`).
  - 확장 영역(전폭): [{시} 전체] 칩(=시 slug 토큰) + 구 칩들. 단일 아코디언(다른 시 펼치면 접힘), 그룹 전환·검색 시 접힘.
  - 시 칩 상태: 시 토큰 선택=selected 스타일, 하위 구만 선택=배지 카운트.
- **검색**: `searchRegions` 그대로(신규 keyword 자동 포함). 결과 행 병기를 `{group}` → 구 레벨은 `{group} · {부모라벨}`.
- 중첩 Modal 없음(기존 구조 유지), 라벨 잘림 해소는 축약 라벨 + 우측 폭 확대로.

## 4-A. 그룹 접두 압축 — URL 한도 실측 결함과 근본 수정 (2026-07-14 구현 중 추가)

**실측 결함**: 그룹 전체를 slug 전수로 확장해 `.in()`에 나열하면, 그룹 4개+(≈160 slug) 선택 시
게이트웨이 URL 한도 초과로 `net::ERR_FAILED` (로컬 스택 실측: 3그룹 119 slug OK / 4그룹 163 slug 실패).
MAX 5단위 규칙상 사용자가 충분히 만들 수 있는 조합.

**수정**: slug 명명 규칙(첫 토큰 = 시·도 축)을 이용해 **그룹 토큰은 like 접두 몇 개로 압축**.

- `regions.ts` `REGION_GROUP_QUERY_PREFIXES` — 그룹별 고유 첫 토큰 파생 (예: 경상 = 부산·대구·울산·경북·경남 5개). 파티션 안전성(타 그룹 slug 미매칭)은 테스트가 가드.
- `regionSelection.ts` `expandRegionTokensToScope(tokens): { slugs, prefixes }` — 그룹→접두, 시/구→기존 확장, 접두에 덮이는 slug 제거. 5그룹 최악 = 접두 14개(URL 수백 B).
- `JobPostingFilters.regionPrefixes` + zod 필드(침묵드롭 방지) + `applyRegionScope`: 접두 존재 시 `or=(location->>region.in.("…"),location->>region.like.접두*,…)` 단일 or 그룹. PostgREST or 내 json 연산자·like·인용 in 혼합은 로컬 실측 검증 완료 (⚠️Windows curl 한글은 cp949 인코딩돼 500 오탐 — node fetch 로 검증해야 함).
- 접두 없으면 기존 in/eq 경로 유지(btree 인덱스 활용). like 접두는 기본 collation btree 를 못 타지만 그룹 광역 선택은 결과 자체가 넓어 seq scan 허용 — 스케일 시 `text_pattern_ops` 인덱스 후속 옵션.

## 6. `findRegionByAddress` 확장

우선순위 (충돌 회피 원칙 유지):

1. **'경기' 명시** → 경기 한정. 일반구까지: 구 keyword 우선, 없으면 시 (예: "경기 수원시 장안구"→`경기 수원시 장안구`).
2. **도명 명시** (강원/충북/충남/전북/전남/경북/경남 + 전체명 강원특별자치도·충청북도·…) → 해당 도 한정, 구 우선→시군. 동명 군(강원 고성군 vs 경남 고성군)은 도명 없으면 매칭하지 않음(도명 명시 시에만).
3. **광역시 keyword 명시** → 그 광역시의 구 우선 매칭, 없으면 시 slug (예: "부산 해운대구"→`부산 해운대구`, "부산 중구"→`부산 중구` — 시 명시 후 구 매칭이라 타 광역시 동명 구와 충돌 없음).
4. 제주(서귀포 우선) — 기존.
5. '서울' 명시 → 서울 구 — 기존.
6. 폴백: 접두 없는 구명은 서울 구 가정 — 기존 유지(수도권 집중 타깃).

### 8-3. UI 특례 — 단일 시 그룹(인천) 승격 규칙
