세 기능(공고 공유 · 워크스페이스 · 주간그리드) 통합 개선의 **전체 설계를 fresh context로 재검토**한다. 구현 전 최종 게이트다 — 이번 세션에서는 **코드를 만들지 않고**, 설계의 정합성·순서·리스크만 검증하고 필요한 수정을 반영한다.

## 배경 (한 줄)

세 기능이 "직원 채우기"라는 한 일인데 3개 화면·3개 어휘로 흩어져 있다. 이걸 "필요→채움→확산" 한 흐름으로 모으고, 안 쓰는 개념(워크스페이스)은 숨기고, 공유(유일한 성장 루프)를 강화한다.

## 아직 설계 안 된 것 (이번에 이어서 하거나 별도)

- **"다음" 레인 ② isSolo 사업장 보이지 않는 기본값** — 단독 사장(지점 1·협업0)이면 워크스페이스/지점 어휘 전부 숨김. 앞선 SP1 홈 재설계 목업에 개념은 있으나 스펙 미작성.
- **"다음" 레인 ③ 홈 "이번 주 채우기" 스트립** — 그리드를 홈의 주인공으로 승격. ①(자동 파생)에 의존.
- grid-auto-sync ①의 **계획(plan)** 문서.

## 재검토 렌즈 (이 순서로)

1. **정합성** — 세 스펙의 결정이 서로 모순되지 않는가? 특히:
   - 용어 교정(now-lane)의 "이번 주 근무표"·"지점"·"필요 인원"이 grid-auto-sync·홈 스트립 설계와 어휘 일치하는가.
   - "워크스페이스"→"사업장" 개명을 now-lane에서 **뺐다**(isSolo와 얽힘). isSolo 설계 시 함께 처리하는 게 맞는지 재확인.
2. **순서(의존성)** — 실제 착수 순서가 옳은가:
   - grid-auto-sync ①은 **seat-basis 브랜치(`feat/seat-basis-posting-count-impl`) 머지·prod 적용 후** (좌석 합 컨벤션 통일). seat-basis 상태 재확인(현재 검증 완료·사용자 게이트 대기).
   - OG(now-lane PR-1B)는 CF 대시보드 env + 배포 사용자 게이트.
   - 그리드 표면 승격(③)은 ①·`weekly_grid_enabled` 플래그 ON 이후.
3. **리스크 재검증** — 각 스펙 §리스크가 여전히 유효한가. 특히 grid-auto-sync D1의 "단독 자동 연결 → 그리드 미사용 사장에게도 dormant 컨테이너 생성" 트레이드오프: 즉시성 우선(현재) vs "지점 존재 시에만 연결"(완화) 중 결정 확정.
4. **누락** — 세 스펙이 개선 보드의 "지금/다음" 레인 항목을 전부 덮는가. 빠진 항목 목록화.

## 검토 방식 (권장)

- fresh context 다각 리뷰: `model: fable` 서브에이전트 2~3인(정합성/순서·리스크/제품 관점)에 스펙 3종 + 개선 보드를 주고 독립 판정 → 메인에서 종합. (agents-v2 모델 라우팅: 판정=fable)
- 또는 `/plan-ceo-review` + `/plan-eng-review`로 CEO·엔지니어 관점 검토.
- 산출: "이대로 구현 OK / 수정 필요 목록 / ②③ 추가 설계 착수 여부".

## 이 세션에서 하지 말 것

- 코드 구현·마이그레이션 작성 금지(재검토 세션임).
- seat-basis 브랜치 건드리기 금지(별도 작업, 사용자 게이트).
- push/PR 금지(명시 요청 시만).

## 검토 후 다음 갈래

- 정합·순서 OK → 우선순위대로 각 SDD 핸드오프로 **구현 세션** 진입(밤샘 근무시간 또는 now-lane부터 — 둘 다 seat-basis 무관하게 착수 가능).

- grid-auto-sync는 seat-basis 머지까지 **대기**.
