- 근거: 코드 실측 (파일:줄 인용). 제품 기준선 = `docs/planning/2026-09-11-work-schedule-product-intent.md`

## 0. 결론 먼저

**셋은 중복이 아니라 한 덩어리인데, 앱이 셋을 남남처럼 다룬다.**
데이터상 `팀 ⊃ 지점 ⊃ 공고 ⊃ 근무기록`으로 한 줄에 꿰여 있고 근무표와 공고는 *같은 테이블의 두 가지 뷰*다.
그런데 화면에서는 서로를 가리키는 링크가 거의 없고, 같은 일(스태프 넣기·정산·인원 계획)을 하는 입구가
각각 2~3개로 갈라져 있다. 그래서 사장이 "어디서 하는 거였지"를 매번 다시 찾는다.

가장 급한 건 중복이 아니라 **두 개의 거짓 정보**다.

| | 증상 | 근거 |
|---|---|---|
| 🔴 P0-1 | 근무표 "필요 인원" 칸이 공고에서 파생된 숫자를 보여주고, 저장하면 그게 수동 목표를 덮는다 | `buildGridCells.ts:37` + `VenueDayPanel.tsx:224` |
| 🔴 P0-2 | 지점 2개 이상인 사장이 지점 칩을 안 고르고 공고를 올리면 그 공고는 근무표에서 **조용히 사라진다** | `venueSelection.ts:37` + `jobManagementService.ts:121` |

### 1.2 데이터 모델의 진실

- **지점(venue)은 별도 테이블이 아니다.** `job_postings` 테이블의 `status='container'` 행이다
  (`JobPostingRepositoryVenue.ts:6`, `baseline_schema_from_prod.sql:3015`).
- `job_postings.venue_id`는 같은 테이블을 가리키는 자기참조 FK다
  (`baseline_schema_from_prod.sql:12783`).
- 근무표가 세는 범위 = `venue_span_posting_ids(V)` = **컨테이너 자신 + `venue_id = V`인 공고들**
  (`baseline_schema_from_prod.sql:9622`).

즉 **근무표 = 날짜 축 뷰, 공고 = 모집 문서 축 뷰**이고, 둘은 같은 `work_logs`를 본다.
"근무표에 나온다/안 나온다"는 오직 `venue_id` 한 칸이 채워졌는지로 갈린다.

### 1.3 세 기능의 역할 (제품 기준선 §2 기준)

| | 제품상 역할 | 실제 화면에서의 위상 |
|---|---|---|
| 근무표 | **내부 운영 계획의 정본** | 버튼 하나 뒤에 숨은 보조 화면 |
| 공고 | 부족 인원을 모집하는 **공개 문서** | 탭 이름이자 1급 목록 |
| 팀 | 협업자 권한 경계 | ⋯ 메뉴 뒤, 1인 사장에겐 빈 껍데기 |

**기준선이 "정본"이라고 부른 것이 UI에서 가장 낮은 위상에 있다.** 이 역전이 아래 마찰 대부분의 뿌리다.

## 2. 중복·마찰 7건

### D1. 확정 스태프 관리가 두 화면 · 액션 집합이 다름

- 근무표: `VenueDayDetail.tsx` → 행 탭 = 근태 편집 시트, 카드 액션 = **빼기(사유 필수)**
- 공고: `StaffManagementTab` (`my-postings/[id]/settlements.tsx:21`) → 명단 제거·상태 변경·노쇼 등

같은 `work_logs`인데 액션이 다르고, 코드가 그걸 설계로 못박아 뒀다
(`VenueDayPanel.tsx` 주석: "파괴적 액션은 진입 맥락의 것 — 화면마다 뜻이 다르다").
사용자에게 보이는 결과는 이렇다 — 근무표에서 공고로 뽑힌 스태프를 빼려 하면
**"이 배치는 뺄 수 없어요. 공고 스태프 관리에서 처리해주세요"** 토스트로 튕긴다
(`VenueDayPanel.tsx:189`). 사장은 지금 그 사람을 보고 있는데, 다른 화면을 찾아가야 한다.

> 제안: 축 통합은 큰 공사다. 대신 **튕기는 토스트를 이동 버튼으로** 바꾼다 —
> "공고 스태프 관리에서 처리해주세요 → [바로 가기]". 그리고 근무표 카드에 출처 공고 칩을 단다.

### D2. 정산이 두 화면 · 범위도 권한도 다름

| | 공고 정산 | 지점 정산 |
|---|---|---|
| 경로 | `my-postings/[id]/settlements.tsx` | `venue-settlements.tsx` |
| 진입 | 공고 상세 타일 "스태프 관리/정산" | 근무표 헤더 "정산" |
| 범위 | 그 공고 1건 | 그 지점 **직접 배치분** 월 단위 (`venue-settlements.tsx:2`) |
| 권한 | 공고 접근자 | **지점 owner 전용** (`work-schedule.tsx:118` `isVenueOwner`) |

"이번 달 인건비 얼마 나갔나"를 보려면 사장이 두 화면을 **머릿속에서 더해야** 한다.
어느 화면에도 "여기 보이는 범위는 ○○입니다"라는 표시가 없다.

> 제안: 지점 정산을 "이 지점 전체(직접배치 + 공고분) 월 뷰"로 승격하고 공고 정산은 그 필터 뷰로.
> 당장은 최소한 양쪽 상단에 범위 한 줄 + 교차 링크.

### D3. 인원 넣는 입구가 세 갈래

1. 근무표 `AddSlotSheet` — 풀 꽂기 / 닉네임 검색 / **공고 열기**
2. 공고 `AddStaffModal` — 닉네임 검색 → 날짜·역할·시간
3. 공고 `applicants` — 지원자 확정

셋 다 결과는 확정 `work_log`다. 폼 프리미티브는 이미 공유돼 있지만(`@/components/staffPicker`)
**입구가 3개고 라벨이 제각각**이다. 특히 AddSlotSheet의 "공고 열기"는 다른 두 모드와 성격이
다르다 — 나머지 둘은 즉시 배치이고 이건 화면 이동이다.

> 제안: "공고 열기"를 3번째 모드에서 빼고, **풀이 비었을 때의 폴백 CTA**로 내린다
> (이미 빈 상태 CTA가 그 역할을 한다 — `AddSlotSheet.tsx:500`). 라벨은 결과 기준으로:
> "이 날 근무에 넣기" / "이 공고에 넣기".

### D4. 🔴 필요 인원이 두 모델인데 한 칸에 섞여 있다 (P0-1)

제품 기준선 §5.1은 **"수동 총원과 공고 파생 인원을 한 입력에 섞지 않는다"**고 못박았다.
UI가 이걸 어긴다.

```
buildGridCells.ts:37   effectiveTarget = Math.max(manual, row.requiredCount)
gridSlotState.ts:47    computeDayCell({ softTarget: effectiveTarget }) → cell.softTarget
VenueDayPanel.tsx:159  const softTarget = cell?.softTarget ?? 0
VenueDayPanel.tsx:224  setTargetInput(softTarget > 0 ? String(softTarget) : '')  ← 입력칸 초기값
VenueDayPanel.tsx:249  setSoftTarget.mutate({ count: parsedTarget })             ← 수동 목표로 저장
```

**결과**: 그 날 공고에 8좌석이 있으면, 수동 목표를 5로 저장해 뒀어도 입력칸에 `8`이 뜬다.
사장이 그 화면에서 저장을 한 번 누르면 수동 목표가 **조용히 8로 덮인다**.
이후 공고를 마감해 좌석이 사라지면, 있지도 않던 목표 8이 남아 매일 "부족 8명"을 외친다.

> 제안:
> - 칩은 출처를 쪼개 보여준다 — `필요 8명 (공고 6 · 수동 2)`
> - 입력칸에는 **수동 목표 실값만** 넣는다 (파생값을 프리필하지 않는다)
> - `useGridSummary` 가 `manualTarget` 을 셀에 함께 실어 내려야 한다 (현재는 max 로 뭉개진 뒤라 복원 불가)

### D5. 🔴 다중 지점에서 공고가 근무표에서 조용히 사라진다 (P0-2)

```
지점 0개 → 기본 지점 자동 생성 후 연결   (jobManagementService.ts:114)
지점 1개 → 그 지점에 자동 연결           (jobManagementService.ts:112)
지점 2개+ → 자동 연결 안 함 (폼 칩에 위임) (jobManagementService.ts:121)
    └ 칩 미선택 → venue_id 없이 발행      (venueSelection.ts:37)
        └ venue_span 에 안 잡힘 → 근무표에 영영 안 보임
```

칩은 **선택 사항**이고, 미선택 발행에 경고가 없다. 다중 지점 사장(= 이 기능이 가장 필요한 사람)이
정확히 이 경로로 떨어진다. 테스트도 이 동작을 "허용"으로 고정해 놨다
(`venueSelection.test.ts:53` — 미선택이면 input 그대로).

> 제안 (택1):
> - (권장) 칩의 **마지막 사용 지점을 기본 선택**한다. 미선택 상태 자체를 없앤다.
> - 또는 미선택 발행 직전에 "이 공고는 근무표에 표시되지 않아요. 계속할까요?" 확인.

### D6. 근무표 → 공고는 "만들기"만 있고 "가기"가 없다

`src/components/workSchedule/` 전체에서 `my-postings` 라우트는 **`create` 두 곳뿐**이다
(`AddSlotSheet.tsx:349`, `VenueDayPanel.tsx:345`).
달력 셀의 `+N 공고` 배지를 눌러도 그 공고로 갈 수 없고, 날짜 패널에 공고 목록도 없다.

반대 방향은 더 비어 있다. `app/` 전체에서 `work-schedule` 참조는 세 곳뿐이다 —
내 공고 탭 버튼, 팀 화면 행, 지점 정산의 뒤로가기 fallback.
**공고 상세에는 근무표로 가는 길이 아예 없다.**

> 제안:
> - 날짜 패널에 "이 날 공고 N건" 섹션 → 각 공고 상세로
> - 공고 상세 관리 타일에 "근무표에서 보기" (그 공고의 첫 근무일로 이동)

### D7. 팀 vs 지점 — 1인 사장에겐 순수 오버헤드

둘 다 자동 생성된다 (`useEnsureDefaultWorkspace`, `useEnsureDefaultVenue`).
이름이 겹쳐 사고가 났던 이력까지 있다 — `work-schedule.tsx:122` 주석:
*"이름은 워크스페이스명 복사가 아니라 `{닉네임}의 지점` — 팀과 지점이 같은 이름이 되던 문제(S1)"*.

홀덤펍 사장 1명 · 지점 1곳이면 두 계층 모두 **선택지가 하나뿐인 선택기**다.
그런데 VenueSelector는 워크스페이스 행과 지점 행을 항상 둘 다 그린다.

> 제안: 팀이 1개이고 멤버가 본인뿐이면 VenueSelector에서 워크스페이스 행을 숨긴다.
> 팀 화면은 "함께 관리할 사람"을 실제로 추가할 때 표면화한다.

## 4. 더 큰 제안 (판단 필요)

지금 "내 공고" 탭은 **공고 목록이 1급, 근무표가 버튼**이다.
그런데 홀덤펍 사장의 하루 루프는 공고가 아니라 근무표 쪽이다 —
누가 오늘 오나 / 안 왔나 / 퇴근을 안 찍었나 / 얼마 줘야 하나.
공고는 그 루프에서 **부족할 때만** 등장하는 보조 수단이다(기준선 §2-1이 정확히 그렇게 정의한다).

탭을 "운영"으로 재정의하고 이렇게 쌓는 안:

```
[운영 탭]
  ├ 오늘        미출근 n · 근무중 n · 퇴근미기록 n   (기준선 §3.1, 아직 미구현)
  ├ 근무표      월 달력 (지금의 work-schedule)
  └ 공고        모집중 n · 마감 n (지금의 목록)
```

이건 되돌린 헤더 아이콘 변경과 반대 방향이다 — 근무표를 **더 숨기는** 게 아니라
**끌어올리는** 쪽. 다만 탭 전체를 바꾸는 일이라 실기기 QA와 함께 별도 웨이브로 다뤄야 한다.
지금 당장은 본문 버튼(복원됨)이 옳은 자리다.
