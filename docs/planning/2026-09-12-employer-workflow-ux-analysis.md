## 0. 결론 먼저

**앱이 "명사"로 나뉘어 있는데 사장은 "동사"로 일한다.**

사장이 하루에 하는 일은 결국 셋이다 — **채운다 / 굴린다 / 준다**.
그런데 화면은 `공고 · 근무표 · 팀`이라는 명사로 잘려 있어서, 동사 하나가 명사 여러 개를 가로지른다.
그래서 같은 일의 시작점이 2~3개고, 끝나는 곳도 제각각이다.

| 사장의 동사 | 지금 흩어진 곳 |
|---|---|
| **채운다** (모집·배치) | 새 공고 작성 · 근무표 부족모집 · AddSlotSheet 공고열기 · AddStaffModal · 지원자 확정 → **5개 입구** |
| **굴린다** (당일 운영) | 공고별 TodayOpsStrip · 근무표 퇴근미기록 배너 · 출퇴근 QR → **공고 N개면 N번 확인** |
| **준다** (정산) | 공고 정산 · 지점 정산 → **2개 화면, 합산은 사장 머릿속** |

가장 효과가 큰 한 수는 새 기능이 아니라 **"오늘" 화면**이다. 필요한 셀렉터가 이미 전부 있다.

## 1. 워크플로우 6종 — 실제 탭 수와 끊기는 지점

### W1. 모집 루프 (공고로 사람 구하기)

```
[경로 A · 공고에서 시작]
내 공고 탭 → 새 공고 작성 → (프리셋 고르기) → 폼 → 발행
  → create-success 화면 → [공유] / [템플릿 저장 제안]                     5~6탭

[경로 B · 근무표에서 시작]
내 공고 탭 → 근무표 → 날짜 탭 → "부족 N명 공고로 모집" → 폼(프리필) → 발행
  → 🔀 완료 화면을 건너뛰고 router.back() + 공유 토스트                    6탭
```

**끊기는 지점 — 같은 행동인데 마무리가 두 가지다.**
`create.tsx:211` 실측: `venueId` 라우트 파라미터로 들어온 경로는 `create-success`를 **우회**한다.
근무표에서 만든 공고만 "템플릿으로 저장" 제안을 영원히 못 본다. 공유 CTA는 토스트로 보상해 뒀지만
6초 뒤 사라지고, 완료 화면의 요약(날짜·출근시간 확인)도 없다.

> 제안: 근무표 경유도 `create-success`를 거치되 1차 CTA를 **"근무표로 돌아가기"**로 바꾼다.
> 마무리 화면이 하나면 "공고를 올렸다"의 느낌이 경로와 무관하게 같아진다.

### W2. 직접 배치 루프 (아는 사람 꽂기)

```
내 공고 탭 → 근무표 → 날짜 탭 → [추가] → 풀/닉네임 → 역할 → (JIT 단가) → 추가   6~7탭
```

콜드스타트가 정직하게 처리돼 있다 — 풀이 비면 죽은 안내문 대신 "공고로 모집하기" CTA
(`AddSlotSheet.tsx:500`). 여기는 잘 돼 있는 쪽이다.

**끊기는 지점**: 같은 일을 공고 쪽에서도 할 수 있는데(`AddStaffModal`), 두 입구가 서로를 모른다.
그리고 넣은 뒤 그 사람을 **다른 날짜에도** 넣으려면 날짜를 바꿔 처음부터 다시 한다
(기준선 §3.2 "한 명을 여러 날짜에 동일 조건으로 배치"는 아직 미구현 — 기준선 §12 P1에 있음).

### W3. 당일 운영 루프 (오늘 굴리기) — **가장 심하게 깨진 곳**

```
공고가 1개일 때:   내 공고 탭 → 공고 카드 → TodayOpsStrip(출근 n/N · 노쇼)        2탭
공고가 3개일 때:   위를 3번 반복. 어느 공고에 오늘 근무가 있는지는 열어 봐야 안다.
퇴근 미기록 확인:  내 공고 탭 → 근무표 → 배너 → 날짜 이동 → 행 탭 → 시트          5탭
출퇴근 QR 띄우기:  내 공고 탭 → 공고 → 헤더 QR 아이콘 → /qr                      3탭 (공고마다)
```

**끊기는 지점 — 오늘을 한눈에 보는 화면이 없다.**
기준선 §3.1이 "오늘" 화면을 위험도 순으로 정의해 놨다(미출근 → 퇴근미기록 → 근무중 → 곧출근 →
완료 → 취소·노쇼). 구현은 **공고 단위 스트립**과 **근무표 배너**로 쪼개져 있어서, 대회사가
공고 3~4개를 동시에 돌리는 D-day에 사장은 화면을 순회해야 한다.

> 제안 (P1, 최우선): **"오늘" 화면을 만든다.** 새 데이터가 필요 없다 — 이미 있는 것들의 조립이다.
> - 미출근/노쇼 = `TodayOpsStrip`이 쓰는 셀렉터 (`my-postings/[id]/index.tsx:271`)
> - 퇴근 미기록 = `summarizeMissingCheckouts` + `useVenueMissingCheckouts` (지점 스팬 전체)
> - 정원 미달 = `selectPostingCapacityGaps` / `toCapacityGapByDate`
> 축을 **공고가 아니라 지점·날짜**로 잡으면 공고 N개가 한 줄로 합쳐진다.

### W4. 정산 루프 (돈 주기)

```
[공고분]  내 공고 탭 → 공고 → "스태프 관리/정산" → 정산 탭 → 개별/일괄 지급완료   5탭
[직접배치분] 내 공고 탭 → 근무표 → 헤더 "정산" → 월 선택 → 지급완료               5탭 (owner만)
```

**끊기는 지점 — "이번 달 인건비"를 묻는 질문에 답할 화면이 없다.** 두 화면의 범위가 다르고
(공고 1건 vs 지점 직접배치분 월 단위), 어느 쪽에도 "여기 보이는 범위" 표시가 없다.
권한도 다르다 — 지점 정산은 `isVenueOwner` 전용(`work-schedule.tsx:118`)이라 편집자는 반쪽만 본다.

> 제안: 지점 정산을 **"이 지점 전체(직접배치 + 공고분) 월 뷰"**로 승격. 공고 정산은 그 필터 뷰.
> 당장 못 하면 최소한 양쪽 상단에 범위 한 줄 + 교차 링크.

### W5. 변경·예외 루프 (취소·노쇼·시간변경)

```
스태프 취소 요청:  공고 → "취소 요청 관리" → 승인/거절                          3탭 ✅ 배지 있음
배치 해제:        근무표 → 날짜 → 카드 빼기 → 사유 입력                        4탭 ✅ 감사 남음
시간 일괄 변경:    근무표 → 날짜 → [시간 변경] → 슬롯 선택 → 저장                 4탭
근태 정정:        근무표 → 날짜 → 행 탭 → 통합 시트                            4탭 ✅ 시트 1개로 수렴
```

여기는 #424에서 편집기 3곳을 한 시트·한 RPC로 수렴시켜 놔서 **일관성이 가장 좋은 구역**이다.

**남은 끊김 하나**: 근무표에서 공고로 뽑힌 스태프를 빼려 하면 토스트로 튕기는데 이동 버튼이 없다
(`VenueDayPanel.tsx:194`). 사장은 그 사람을 눈앞에 두고 다른 화면을 직접 찾아가야 한다.

### W6. 협업 루프 — **개념이 둘인데 구분 기준이 안 보인다**

```
팀 멤버 초대:      내 공고 탭 → ⋯ → 팀 → [+ 초대]           → 팀의 모든 공고 권한
공고 협업자 추가:   공고 → "함께 관리할 사람"                  → 그 공고 하나만
```

이름이 둘 다 "함께 관리하는 사람"이다. 사장이 어느 쪽을 써야 하는지 판단할 근거가 화면에 없다.
게다가 팀 화면은 1인 사장에게 선택지 하나뿐인 빈 껍데기다(멤버=본인, 팀=1개).

> 제안: 팀 화면 진입을 **멤버가 2명 이상이거나 초대를 보낸 적이 있을 때만** 노출.
> "함께 관리할 사람" 화면 상단에 한 줄: *"이 공고만 함께 봅니다. 모든 공고를 맡기려면 팀에 초대하세요."* + 링크.

## 2. 공고 상세 화면 — 진입점 12개가 한 화면에

실측(`my-postings/[id]/index.tsx:650-757` + 헤더):

| 위치 | 진입점 |
|---|---|
| 헤더 | 미리보기(눈) · 공유 · **출퇴근 QR** · ⋯(마감/삭제/재게시) |
| 타일 | 라이브 운영 · 지원자 관리 · 취소 요청 관리 · 스태프 관리/정산 · 공고 수정 · **지원 QR** · 스태프 공지 · 함께 관리할 사람 |
| 상단 | "지금 할 일" 승격 카드 (같은 목적지가 한 번 더) |

**문제 1 — 사람을 다루는 타일이 셋인데 이름이 비슷하다.**
`지원자 관리`(들어온 사람) · `스태프 관리/정산`(확정된 사람) · `함께 관리할 사람`(협업자).
세 단어가 다 "관리"로 끝나서 이름만으로는 구분이 안 된다.

**문제 2 — QR 두 개의 위치 규칙이 없다.**
지원 QR은 **타일**, 출퇴근 QR은 **헤더 아이콘**. 코드는 이미 라벨로 방어 중이지만
(`'지원'을 앞에 둔다 — '공고 QR'이라고만 하면 출퇴근 QR과 구분되지 않는다`),
같은 종류의 물건이 다른 층에 있으면 라벨로는 못 고친다.

> 제안:
> - 이름을 **대상**으로 바꾼다: `지원자 관리` → 그대로 / `스태프 관리/정산` → **`근무·정산`** /
>   `함께 관리할 사람` → **`협업자`**
> - QR 둘을 같은 층(타일)에 나란히 두고 목적어를 붙인다: `지원받는 QR` · `출퇴근 QR`

**잘 돼 있는 것 — 건드리지 말 것**: "지금 할 일"로 승격돼도 타일 목록에서 빼지 않는 규칙
(`index.tsx:762` 주석, 실사고 제보 반영). 진입점 자리가 신호에 따라 움직이면 사장은
"메뉴가 없어졌다"고 읽는다. 이 원칙은 다른 화면에도 확대 적용할 가치가 있다.

## 3. 숨은 정합성 위험 — 급여 정본이 둘이다

| | 저장 위치 | 쓰는 경로 | 미설정 시 |
|---|---|---|---|
| 지점 역할 단가 | 컨테이너 `roleSalaries` | 근무표 직접 배치 | **₩15,000 폴백** + "기본 단가 적용" 배지 |
| 공고 급여 | 공고 `compensation` | 공고로 확정된 스태프 | 공고 필수 입력 |

같은 딜러가 같은 날 **직접 배치로 한 번, 공고로 한 번** 들어오면 시급이 다를 수 있고,
두 정산 화면이 그걸 각각 계산한다. 폴백은 배지로 가시화해 뒀지만(조용한 오답 금지 정책),
**두 정본이 평행하다는 사실 자체**는 어디에도 안 보인다.

> 제안: 지점 단가표를 기본값으로 두고 **공고 작성 시 그 값을 프리필**한다. 공고에서 바꾸면
> 그 공고만의 예외로 표시. 정본은 하나, 예외는 명시 — 지금은 정본이 둘이라 어느 쪽이 맞는지
> 사람이 판단해야 한다.

## 5. 더 큰 그림 (판단 필요)

동사로 나눈다면 탭은 이렇게 된다:

```
[운영]  오늘 · 근무표 · 공고        ← 지금의 "내 공고" 탭을 확장
[정산]  지점 월 정산(공고분 포함)
[설정]  팀 · 지점 · 협업자
```

지금 "내 공고"라는 탭 이름이 **모집 문서**를 가리키는데, 정작 그 탭이 담아야 하는 건
사장의 **하루 전체**다. 이름이 내용을 좁히고 있다.

다만 이건 탭 구조 변경이라 실기기 QA를 낀 별도 웨이브 감이다.
지금 당장은 P1-a("오늘" 화면)만으로도 W3의 순회 문제가 해소된다.

## 6. 이번 세션에서 실제로 바꾼 것

| | 내용 | 검증 |
|---|---|---|
| 되돌림 | 내 공고 탭 근무표 진입점: 헤더 아이콘 → 본문 버튼 | tsc 0 · eslint 0 · jest 11건 |
| P0-1 | 목표 인원 입력칸이 공고 파생값을 수동 목표로 덮어쓰던 문제 | red-green 확인 · 영향권 1,192건 |
| P0-2 | 다중 지점 칩 미선택 발행 → 근무표 무음 유실 차단 | 낡은 계약 테스트 1건 갱신 |

위 §1~§5는 **읽기 전용 분석**이며 아직 구현하지 않았다.
