# 근무표 제품 기획 의도 및 완성 기준

- 작성일: 2026-09-11
- 상태: 사용자 합의 완료 · 구현 기준선
- 대상: 구인자 `work-schedule`, 스태프 `schedule`, 공고·출퇴근·정산 연결부

## 1. 제품 정의

근무표는 단순 달력이 아니라 구인자가 인력 계획부터 현장 운영과 지급까지 처리하고,
스태프가 확정된 근무 약속부터 출퇴근과 지급 결과까지 확인하는 통합 인력 운영 도구다.

핵심 흐름은 다음과 같다.

`필요 인원 계획 → 확정 배치 또는 공고 모집 → 근무 확정 → 출퇴근 → 예외 처리 → 정산`

홀덤펍과 대회사는 동급 사용자다. 계정이나 지점에 고정된 모드를 두지 않고 같은 데이터에
대해 홀덤펍은 오늘 운영·다중 날짜 배치를, 대회사는 기간·역할별 충원 관점을 주로 사용한다.

## 2. 핵심 원칙

1. 근무표가 내부 운영 계획의 정본이고 공고는 부족 인원을 모집하는 공개 문서다.
2. 계획의 최소 단위는 `날짜 + 역할 + 출근 예정시간 + 필요 인원`이다.
3. 알 수 없는 예정 퇴근시간은 수집하거나 추정하지 않는다.
4. 지원은 배치가 아니다. 구인자가 확정한 슬롯만 확정 인원과 근무 기록에 포함한다.
5. 직접 배치는 사전에 합의가 끝난 스태프의 확정 배치만 지원한다.
6. 출퇴근·정산·취소·노쇼 기록은 삭제로 해결하지 않고 상태와 변경 이력으로 보존한다.
7. 공개 공고와 사용자 알림은 자동 실행하지 않고 영향 확인 또는 재시도 가능한 절차를 둔다.
8. `0건`, `조회 실패`, `오프라인 캐시`를 서로 다른 상태로 표시한다.

## 3. 구인자 정보 구조

### 3.1 오늘

현장 대응 화면이며 위험도가 높은 순서로 정렬한다.

1. 미출근 확인 필요
2. 퇴근 미기록
3. 근무 중
4. 곧 출근
5. 오늘 완료
6. 취소·노쇼 기록

전화·문자, 수동 근태 정정, 노쇼 기록을 제공한다. 자동 퇴근은 사용하지 않는다.

### 3.2 일정

- 월 보기: 날짜별 부족·배치·주의 신호
- 주 보기: 역할·출근시간별 상세 배치
- 오늘로 이동
- 필요 인력 설정
- 확정 스태프 배치
- 한 명을 여러 날짜에 동일 조건으로 배치
- 출근 전 역할·출근시간 수정 및 배치 해제
- 변경 이력 확인

반복 규칙은 1차 범위에서 제외한다. 사용자가 여러 날짜를 직접 선택하면 날짜별 독립 근무를
원자적으로 생성한다. 날짜마다 다른 조건을 한 번에 편집하는 기능도 후속으로 둔다.

### 3.3 충원

날짜·역할·출근시간별 필요/확정/부족 인원과 연결 공고 상태를 보여준다.
주요 행동은 `확정 스태프 배치`와 `부족 인원 모집` 두 가지다.

### 3.4 정산

- 퇴근 미기록
- 정산 확인 필요
- 지급 대기
- 지급 완료
- 기간·스태프·상태 필터
- 개별·일괄 지급 완료

퇴근 미기록은 현재 보고 있는 달과 무관하게 해결 전까지 계속 노출한다.

## 4. 스태프 내 일정

- 조회 월과 무관한 실제 미래 전체의 가장 가까운 확정 근무
- 월 달력과 목록 전환
- 지원 중·확정·완료·취소·노쇼 상태
- 지점, 역할, 출근 예정시간, 급여 조건
- QR 출퇴근
- 취소 요청
- 정산 내역과 변경 이력
- 같은 날 다른 근무가 있을 때 확인 경고

예정 종료시간이 없으므로 일정 충돌을 확정 판정하거나 차단하지 않는다. 같은 날 일정이 둘 이상이면
퇴근시간을 확인하라는 경고만 제공한다.

## 5. 인력 계획과 공고

### 5.1 수치의 의미

- 필요 인원: 실제 운영 목표
- 확정 인원: 직접 배치 또는 공고 지원에서 확정된 인원
- 부족 인원: `max(필요 인원 - 확정 인원, 0)`
- 모집 인원: 외부 공고에서 추가로 모집할 인원

날짜별 총 필요 인원은 역할·출근시간별 계획을 합산한 읽기 전용 요약이다. 수동 총원과 공고 파생
인원을 한 입력에 섞지 않는다.

### 5.2 공고 초안

`부족 인원 모집`은 지점·주소·날짜·역할·출근시간·부족 인원·급여·연락처를 채운 공고 초안을
만든다. 제목, 상세 업무, 복장·준비물, 제공 사항, 지원 조건, 지원 마감, 공개 범위를 확인한 뒤
구인자가 발행한다. 자동 발행하지 않는다.

하나의 공고에 여러 날짜·역할 슬롯을 담을 수 있다. 지원자는 가능한 슬롯을 선택하고 구인자는
슬롯별로 확정한다. 확정 시 날짜별 독립 work log를 생성한다.

### 5.3 발행 후 변경

- 지원자 없음: 즉시 변경 가능
- 미확정 지원자 있음: 변경 후 지원자 알림
- 확정 스태프 있음: 영향과 대상을 확인한 뒤 적용
- 모집 인원을 확정 인원보다 작게 줄일 수 없음
- 공고 마감·삭제가 이미 확정된 근무를 삭제하지 않음

## 6. 시간과 근태

- 예정 출근시간: 구체 시각 또는 협의/미정
- 예정 퇴근시간: 저장하지 않음
- 실제 출퇴근시간: QR 또는 권한 있는 사용자의 수동 정정
- 실제 스캔 시각과 정정된 시각을 모두 보존
- 수동 정정에는 사유가 필수
- 출근 예정시간이 지났으면 `미출근 확인 필요` 신호를 표시
- 출근시간 미정에는 지각 신호를 만들지 않음
- 자동 지각 확정·급여 차감은 하지 않음
- 퇴근 미기록이면 근무시간과 시급 총액을 확정하지 않음

## 7. 확정 배치, 변경, 취소, 노쇼

### 7.1 확정 배치

- 사전 합의된 스태프만 배치
- 추가 즉시 양쪽 일정에 확정으로 반영하고 알림
- 별도 수락·거절은 1차 범위에서 제외
- 최초 사용과 배치 화면에 사전 합의 원칙을 안내
- 누가 언제 배치했는지 이력 보존

### 7.2 변경과 해제

- 출근 전에는 역할·출근시간 수정 가능
- 여러 날짜 중 `이 날짜만` 수정
- 변경 시 스태프 알림
- 출근 전 배치 해제는 사유 필수
- 출근 후에는 일반 `근무 빼기` 금지, 근태 정정만 허용
- 정산 완료 후 일반 수정 금지, 관리자 정정 절차 사용

### 7.3 스태프 취소 요청

`확정 → 취소 요청 중 → 승인 또는 거절` 상태를 사용한다. 요청 중에는 확정을 유지하고,
승인되면 해당 슬롯만 해제하여 부족 인원을 다시 계산한다. 임박한 근무에는 전화·문자 경로를
함께 제공한다. 출근 후에는 취소 요청할 수 없다.

### 7.4 노쇼

출근 예정시간 경과는 노쇼 확정이 아니라 확인 신호다. 구인자가 연락 후 사유를 입력해 노쇼로
기록한다. 노쇼는 취소와 다른 상태이며 구인자 근무표에서도 사라지지 않는다. 스태프에게 사유와
문의 경로를 제공한다.

## 8. 급여와 정산

1차 급여 유형은 시급과 일급이다. 월급과 휴게시간 차감은 제외한다.

- 시급: 실제 출근부터 실제 퇴근까지 계산
- 일급: 약정 금액 적용
- 추가 지급·차감: 별도 조정 항목과 사유로 기록
- 퇴근 전 또는 퇴근 미기록: 예상 총액을 확정 표시하지 않음
- 지급 전: 구인자가 계산 근거 확인
- 지급 완료: 일반 수정 잠금, 스태프에게 내역 알림
- 0원 정산: 사유를 입력한 명시적 확정만 허용

정산에는 단가, 실제 출퇴근, 인정 근무시간, 기본 급여, 조정, 공제, 최종액, 처리자와 처리 시각을
보여준다. 원본 출퇴근 기록을 금액 값으로 덮어쓰지 않는다.

## 9. 권한

- owner: 전체 권한, 지점 설정, 급여 단가, 정산·지급 완료, 삭제성 작업
- workspace editor/member: 인력 계획, 확정 배치, 공고, 출퇴근 확인·정정
- 조회 전용 역할이 존재하면: 일정과 당일 현황만 조회
- global admin: 기본 조회, 수정 시 관리자 전용 정정·사유·감사 이력

급여 단가와 최종 지급은 owner로 제한한다. 앱 안내 문구와 RLS/RPC 권한을 같은 계약으로 맞춘다.

## 10. 알림과 이력

스태프에게 확정 배치, 날짜·시간·역할·급여 변경, 배치 해제, 취소 요청 처리, 노쇼, 정산 확정,
지급 완료를 알린다. 여러 날짜 변경은 한 통으로 묶는다. 내부 메모와 배치 색 변경은 알리지 않는다.

알림 실패는 데이터 변경을 롤백하지 않는다. 재시도 큐에 남기고 구인자에게 일부 알림 실패를
표시한다. 각 근무에는 변경 전후 값, 처리자, 처리 시각, 사유를 보존한다.

## 11. 로딩·오류·오프라인

- `0건`, `조회 실패`, `오프라인 캐시`, `일부 성공`을 구분한다.
- 요약 실패 시 0명으로 표시하지 않고 부족 계산·목표 수정·공고 생성을 잠근다.
- 퇴근 미기록 조회 실패를 숨기지 않고 마지막 확인 시각과 재시도를 제공한다.
- 오프라인에서는 마지막 동기화 시각과 함께 일정·연락처를 읽을 수 있다.
- 오프라인 쓰기, QR 성공 처리, 공고 발행, 지급 완료는 1차에서 허용하지 않는다.
- 저장 중 버튼 잠금, 더블탭 방지, 서버 상태 재검증, 실패 시 입력 보존을 적용한다.

## 12. 현재 구현 격차

### P0: 데이터 신뢰와 파괴 방지

- work_logs 변경이 스태프 일정의 실시간 경로에 반영되지 않음
- 지원서 LIMIT 기반 조회로 장기·다중 일정이 월 화면에서 누락될 수 있음
- 취소 RPC가 terminal work log와 application 상태를 모순되게 만들 수 있음
- 실시간 소스 전환에서 월 경계 일정이 유실될 수 있음
- 구인자 그리드·퇴근 미기록 조회 실패를 0건처럼 취급
- 출근 이후 근무 빼기와 근태 정정의 경계 불일치
- 일정 카드의 중첩 버튼과 접근성 트리 결함

### P1: 핵심 사용자 흐름

- 날짜·역할·출근시간별 필요 인원 모델 및 편집 UI
- 한 명을 여러 날짜에 확정 배치하는 원자적 RPC/UI
- 부족 슬롯에서 공고 초안 생성과 슬롯별 연결
- 조회 월과 독립된 다음 확정 근무
- 노쇼를 구인자 일별 상세에 기록으로 보존
- 필터 빈 상태와 가장 가까운 일정 이동 정합
- 스태프 풀 조회 실패와 진짜 빈 상태 분리
- 출근 전 배치 해제 사유와 변경 이력

### P2: 운영 효율과 품질

- 오늘·일정·충원·정산 정보 구조
- 월/주 보기와 오늘 복귀
- 대형 목록 가상화
- 팀·지점 선택기의 웹·키보드 UX
- 상태 변경 알림 묶음과 알림 실패 표면
- 역할별 권한 안내와 서버 권한 정합
- 구인자 근무표 및 역할 간 E2E

### 유지

- 고정 QR의 상태 기반 출퇴근
- 자동 퇴근을 만들지 않는 정책
- 실제 출퇴근 기반 정산
- 날짜별 독립 work log
- 공고의 다중 날짜·슬롯 지원
- 취소 요청과 노쇼의 별도 상태
- 오프라인 읽기 캐시

### 후속 제외

- 수락·거절이 있는 근무 요청
- 반복 규칙과 반복 일정 전체 수정
- 여러 명 × 여러 날짜 매트릭스 일괄 배치
- 예정 퇴근시간과 자동 충돌 차단
- 월급, 휴게시간 자동 차감
- 오프라인 쓰기 동기화
- 공고 자동 발행

## 13. 완료 기준

1. 구인자는 날짜·역할·출근시간별 필요 인원을 만들고 부족분을 공고 또는 확정 배치로 채울 수 있다.
2. 한 명을 여러 날짜에 배치해도 일부 실패 없이 전부 성공하거나 전부 롤백된다.
3. 공고 확정·직접 배치·취소·노쇼·근태·정산이 양쪽 화면에서 같은 상태로 보인다.
4. 출근 이후 기록은 일반 삭제로 사라지지 않으며 모든 정정에 감사 이력이 남는다.
5. 조회 실패를 0명·빈 상태로 오인하지 않는다.
6. 다음 근무, 미출근, 미퇴근, 부족 인원, 정산 대상을 사용자가 즉시 찾을 수 있다.
7. owner/editor/admin 권한이 UI와 RLS/RPC에서 일치한다.
8. 핵심 역할 간 흐름을 Jest, pgTAP, E2E와 실기기 QA로 검증한다.

## 14. 2026-09-11 구현 결정 기록

이 섹션은 기획 의도를 바꾸지 않고, 구현 중 발견한 데이터 손실·권한·정산
위험에 대한 더 안전한 판정을 기록한다.

- 완료: 월 요약·퇴근 미기록·스태프 풀 조회 실패를 0건과 분리하고 재시도를 제공한다.
- 완료: 월 요약을 신뢰할 수 없으면 헤드카운트에 의존하는 계획·배치·공고
  쓰기는 잠그되, 이미 조회된 개별 근무의 출퇴근 정정 진입은 열어 둔다.
- 완료: 퇴근 미기록은 현재 표시 월이 아니라 지점 스팬 전체의 과거
  `checked_in`을 별도 조회한다.
- 완료: 스태프의 다음 근무는 현재 월 목록이 아니라 오늘 이후 `scheduled/checked_in`
  work log 중 가장 빠른 1건을 서버 정렬로 조회한다.
- 완료: 지원서 읽기는 단일 `LIMIT`를 제거하고 페이지를 끝까지 읽은 뒤 슬롯
  날짜로 필터한다.
- 완료: `allowDeleteAnyStatus` 탈출구를 제거했다. 일반 제거는 `scheduled`만 노출하고,
  출근 이후·취소·노쇼는 정정/감사 흐름으로만 다룬다.
- 완료: 직접 배치 해제는 2~200자 사유, 출근 전 상태·시각, 미정산을
  서버에서 재검증하고 append-only `work_schedule_audit_events`에 before/after·actor를 남긴다.
- 완료: 정산 상태·금액·지급일·메모 변경은 owner만 허용하고, 0원 확정은
  사유를 필수로 한다. 정산 완료 후 일반 슬롯·근태·노쇼 수정은 서버 트리거로 잠근다.
- 검증 추가: 안전 계약 카탈로그(pgTAP), 직접 배치 해제 사유 UI, 다음 근무의
  실제 날짜·시간 파싱 경로를 회귀 테스트에 고정했다.
- 리뷰 후 보강: 레거시 시간 미정·범위값을 배치 해제 시 안전하게 판정하고,
  정산 완료 행의 일반 사용자 되돌리기·금액 수정 우회를 잠갔다. 지원서 전량
  조회는 5,000행 안전 상한에서 명시적 실패로 전환해 불완전한 계획을 쓰지 않는다.
- 권한 UI: 지점 설정과 정산 진입은 지점 owner에게만 노출한다. 편집자의
  배치·공고·근태 권한은 유지한다.
- 보류: 역할+시작시각별 1급 계획 테이블과 공고 슬롯 FK는 기존 `schedule.requirements`
  데이터의 무손실 백필·이중 읽기 계약이 필요하다. 본 변경에서 부분 이식으로 두
  정본을 만들지 않고 별도 마이그레이션 웨이브로 남긴다.
- 보류: global admin 감사 정정 전용 UI/RPC, 노쇼 전용 RPC·오늘 운영 IA,
  다중 슬롯 공고 초안, 역할 매트릭스 E2E는 독립 통합 검증과 실기기 QA가 필요하다.
