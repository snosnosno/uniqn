**규칙**: 설계 계약 대조 리뷰에서 다음 3축은 코드가 green 이어도 빠진다 — 별도 대조 필수.

**Why:** 2026-08-07 조건 유도 그룹핑 대조 리뷰 실증(543/543 green·tsc 0·knip 0 인 브랜치에서 3건 검출):

1. **다이어그램 라벨 형식**: 설계 §3.2 가 "카드A: 8/10~8/11 · 8/13" 을 그렸고 §3.8 이 "summarizeGroupDates 확장"을 명시했는데, 함수는 미확장 — 비연속 날짜는 "8/10 외 2일"로 렌더. 어떤 테스트도 라벨 **형식**을 설계 다이어그램과 대조하지 않아 침묵. 요약/포맷 함수가 "확장 대상"으로 명시되면 diff 에 그 함수가 있는지부터 확인.
2. **사용자 최종게이트 결정의 변형**: 결정 21(F10 승계 액션=카드 선택 액션시트, 사용자 A안 확정)을 구현이 "예외 추출 시트 재사용"으로 대체하고 근거 주석을 달았다. 근거가 성립해도(자산 부재·동일 목적지) **취향 결정을 사용자 게이트로 확정한 항목**은 리뷰어가 정당 판정으로 닫으면 안 되고 PR 에서 사용자 재가를 요구해야 한다.
3. **F-minor 나열식 명세**: "카드 10+ 는 월 구분 서브헤더" 같은 한 줄짜리 나열 항목이 통째로 미구현돼도 아무 신호가 없다 — F1~F13 은 개별 대조했지만 F-minor 꼬리는 놓치기 쉽다. 나열 명세는 항목별 grep 체크리스트로.

**How to apply:** 설계 문서에서 ① ASCII 다이어그램의 문자열 리터럴 ② "사용자 결정/최종 게이트" 표기 행 ③ 나열식(·구분) 명세 문장을 먼저 추출해 체크리스트를 만들고, 코드 대조는 그 다음에 한다. 이번 브랜치의 정당 이탈 선례(재인용용): 빈 상태 정의 축소(날짜0+조건0 — 규칙 0 템플릿 보존과 정합), E2 좌표계 축소(같은 렌더 사이클=재계산이라 stale 불가, 시간 넘는 2경로만 날짜집합 앵커), ORDER-8 교체(상한은 DatePickerModal remainingSlots 가 그대로 강제 — existingDates=[] 이면 상한=maxDates), normalize 빈시드 비책임(화면 commitGroups 가 계약 이행).
