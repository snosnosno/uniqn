- 작성: 2026-07-23
- 상태: 설계 확정 (구현 계획 미착수)
- 범위: **표시 계층 전용**. DB 마이그레이션·서버 가드·저장 형식 변경 없음.

## 1. 배경 — 같은 공고가 화면마다 다른 숫자

그룹 공고(8/22~8/23, 매일 딜러 5명)에서:

| 화면            | 현재 표시                          | 근거                                                 |
| --------------- | ---------------------------------- | ---------------------------------------------------- |
| 공고 카드       | `딜러 10명 (3/10)`                 | 그룹 요약이 `count = perDayCount × dayCount` 로 곱셈 |
| 공고 상세(일별) | `딜러 5명 (2/5)`, `딜러 5명 (1/5)` | 일별은 하루치                                        |

두 값 모두 내부적으로는 정합(10 = 5+5, 3 = 2+1)하지만 **`N명` 라벨의 기준(하루치 vs 합계)이 화면마다 달라** 모순으로 읽힌다.

관련 코드:

- 곱셈 지점: `src/components/jobs/shared/postingSurfaceModel.ts:319-335`
- 표시 문자열: `src/components/jobs/shared/PostingScheduleContent.tsx:278` — `formatRoleLine` = `` `${role.label} ${role.count}명 (${role.filled}/${role.count})` ``

## 2. 핵심 결정

### 2.1 데이터: 자리(좌석) 단일 소스

모든 숫자는 **자리 = (날짜 · 시간슬롯 · 역할) 한 칸** 에서 파생한다. 두 값만 존재한다.

| 값          | 유일 소스                                                                                       |
| ----------- | ----------------------------------------------------------------------------------------------- |
| 필요 자리   | 일정(schedule)에서 자리 합산 — `Σ GREATEST(count, headcount, 0)`                                |
| 채워진 자리 | 확정 집계(`count_posting_confirmed_by_slot` → `usePostingFilledCounts`), cancelled·no_show 제외 |

`schedule.roles[].filled`(SP3 dead counter, 항상 0)는 **표시·판정 어디서도 읽지 않는다.** 3축 발산의 뿌리를 여기서 끊는다.

### 2.2 표시: 하루 기준 한 줄 + (구인자) 자리 총계 병기

```
[시간] [역할] [하루 요구]명 ([가장 찬 날 확정]/[하루 요구])
```

- 분모 = **하루치 요구 인원**(`perDayCount`). 곱셈하지 않는다.
- 분자 = **날짜별 확정 수의 최대값** `max(filled_d)`.
- 구인자 화면에만 한 줄 추가: `자리 M/T 채움` (T = 자리 총합, M = 채워진 자리 합).

예시(8/22에 2명, 8/23에 1명 확정):

| 화면             | 표시                                              |
| ---------------- | ------------------------------------------------- |
| 구직자 카드      | `18:00 딜러 5명 (2/5)`                            |
| 구직자 상세 요약 | `딜러 5명 (2/5)`                                  |
| 구직자 상세 일별 | `8/22 딜러 2/5` · `8/23 딜러 1/5`                 |
| 구인자 카드      | `18:00 딜러 5명 (2/5)` + `자리 3/10 채움`         |
| 구인자 상세 현황 | `배정 현황 3/10명` _(현행 유지 — 이미 자리 기준)_ |

### 2.3 왜 최대값인가 (타협이 아니라 정의)

연속 날짜 그룹은 **통으로만 지원**된다(`AssignmentSelector.tsx:102-128` — 그룹 선택 시 `group.dates` 전체를 한 번에 배정). 따라서 새 지원자는 **모든 날짜에 자리가 있어야** 수용된다.

```
추가 수용 가능 인원 = min over d ( perDayCount − filled_d )
                   = perDayCount − max(filled_d)
```

즉 `분자 = max(filled_d)` 를 쓰면 `분모 − 분자` 가 **정확히 실제 남은 자리**가 된다. 평균·합계는 이 성질을 갖지 않는다.

### 2.4 마감 판정과 대기 지원

- `max(filled_d) ≥ perDayCount` → 그룹 통지원으로 더 받을 수 없음 → **"마감"** 표시.
- 마감이어도 **지원 접수는 허용**(현행 정책 유지). 취소로 자리가 나면 구인자가 확정.
- ⚠️ **자동 대기 승계 기능은 없다** — 지원 상태는 `pending/approved/rejected` 뿐(`src/types/application.ts`). 문구가 자동 배정을 암시하지 않도록 한다(예: `대기 지원` 허용, `순번대로 자동 배정` 류 금지).
- 최종 정원 초과는 서버 `MAX_CAPACITY_REACHED` 가 이중 차단(현행).

## 3. 공고 형태별 적용

| 형태                       | 분모                                      | 분자            | 자리 총계 병기                                      |
| -------------------------- | ----------------------------------------- | --------------- | --------------------------------------------------- |
| 그룹 연속날짜 (dayCount>1) | 하루 요구                                 | `max(filled_d)` | **표시**(구인자)                                    |
| 단일 날짜                  | 그 날 요구                                | 그 날 확정      | 생략(요약과 동일)                                   |
| 비그룹 다중날짜            | 날짜별 섹션이 각각 dayCount=1 → 자동 정합 | 그 날 확정      | 생략                                                |
| 상시(fixed)                | 역할 요구                                 | 확정            | 생략                                                |
| container(운영처)          | —                                         | —               | **인원 표시 자체를 하지 않음**(자리 0, 트리거 SKIP) |

## 4. 예외 매트릭스

| 상황                          | 카드 요약 `(max/5)` | 자리 총계 | 특수 로직                                                      |
| ----------------------------- | ------------------- | --------- | -------------------------------------------------------------- |
| 균등 (8/22=2, 8/23=2)         | `(2/5)`             | `4/10`    | 없음                                                           |
| 불균등 (8/22=2, 8/23=1)       | `(2/5)`             | `3/10`    | 없음                                                           |
| 한 날만 만석 (8/22=5, 8/23=1) | `(5/5)` **마감**    | `6/10`    | 없음 — 통지원 불가가 맞고, 8/23 공백은 자리 총계·일별에서 보임 |
| 그리드 직접배치(단일 자리)    | 해당 날 +1 반영     | +1        | 없음                                                           |
| 부분 확정                     | 확정한 날만 반영    | +N        | 없음                                                           |
| 취소·노쇼                     | 해당 날 −1          | −1        | 없음                                                           |

**"한 날만 만석"이 이 설계의 핵심 시험**: 구직자에겐 정직하게 마감(실제로 통지원 불가), 구인자에겐 자리 총계 `6/10` 과 일별 상세로 "8/23이 비었다"가 드러난다. 두 관점이 서로 다른 질문에 답하며 모순되지 않는다.

## 5. 불변식 (테스트로 고정)

1. `카드 요약 분자 == max(일별 분자)` — 요약과 일별이 갈라지지 않음
2. `자리 총계 분자 == Σ(일별 분자)` , `자리 총계 분모 == Σ(일별 분모)`
3. `카드 요약 == 상세 요약` (같은 문자열)
4. `dayCount == 1` 이면 `요약 == 일별 == 자리 총계`
5. 마감 표시 조건 `max ≥ perDayCount` 와 "대기 지원 버튼 활성"은 **동시에 성립**한다(의도된 정책)

## 6. 변경 반경

**바꾸는 것 (표시 계층)**

- `postingSurfaceModel.ts` 그룹 요약: 곱셈 제거 → 분모 = `perDayCount`, 분자 = `max(일별 filled)`
- `PostingScheduleContent.tsx` `formatRoleLine` — 하루 기준 문법 통일
- 구인자 카드/상세: 자리 총계 병기 라인 추가
- 지원 화면(`AssignmentSelector` 계열)에 확정 집계 주입 — 현재 미주입이라 항상 `(0/N)` 으로 표시됨
- **그룹 경계 통일**: 카드(`utils/date/grouping.ts:209`, headcount 비교)와 지원 화면(`utils/assignment/selectionUtils.ts` `getRoleStructureKey`, 역할 종류만 비교)이 그룹을 다르게 묶는다 → 단일 기준 함수로 통일
- `utils/job-posting/dateUtils.ts:215` stale 주석("역할별 peak의 합") 정정
- 타임 슬롯 표시 정렬(시작시간 오름차순, TBA 뒤) — 실기기 스크린샷 실측 버그(10:00→11:00→10:30 등록 순서 그대로 노출)
- 일수 인라인 표기(사용자 결정 2026-07-23): `formatDateRangeWithCount` 를 단일 행 `"8/22(토) ~ 8/23(일) · 2일"` 로 — 카드 split·별도 일수 행 제거, 상세·지원화면 라벨 자동 정합

**안 바꾸는 것**

- DB 마이그레이션·트리거·`MAX_CAPACITY_REACHED` 가드 — 이미 자리 기준으로 정합
- 저장 형식(`schedule.roles[].count` = 하루치, `filled` = 0 유지) — `get_venue_grid_summary`·`_total_positions_from_schedule` 가 이 형식을 SQL에서 직접 파싱하므로 **불변 필수**
- 구인자 상세 `배정 현황 M/T` — 이미 자리 기준

## 7. 테스트 전략 (RED 우선)

1. 지원 화면에 확정 5/5 주입 → "마감" 표시 + 대기 지원 버튼은 활성 **(현행 반드시 실패)**
2. 불균등(2,1) → 카드 `(2/5)`, 자리 총계 `3/10`
3. 한 날만 만석(5,1) → 카드 `(5/5)` 마감, 자리 총계 `6/10`
4. 요약 == 일별 max 불변식 (§5-1)
5. 그룹 경계에 headcount 반영 — 카드와 지원 화면이 같은 그룹을 만든다
6. `dayCount==1` 회귀 — 기존 표시 불변

## 8. 미검증 가정 (구현 계획에서 확인할 것)

- **상시(fixed) 공고의 확정 집계 키 처리** — fixed 는 날짜가 없어 `count_posting_confirmed_by_slot` 의 키 구성이 dated 와 다를 수 있다. 코드로 확인 후 §3 표를 확정한다.
- 구인자 카드에 자리 총계 한 줄 추가 시 카드 높이 증가 — 목록 밀도 영향 확인 필요.

## 9. 결정 이력

| 검토                                      | 결론                                                                                                |
| ----------------------------------------- | --------------------------------------------------------------------------------------------------- |
| 사람 기준(그룹=1자리) vs 자리 기준        | **자리 기준** — 사람 기준은 불균등·직접배치·부분확정에서 표현 불가, DB에 "그룹 통째 확정" 개념 없음 |
| 카드에 자리 총합(10) 표기 vs 하루 기준(5) | **하루 기준** — 통지원 전제에서 `max` 분자가 실제 남은 자리를 정확히 표현하고, 라벨이 길어지지 않음 |
| 구직자에게 확정 수 노출                   | **노출**(분수 그대로) — 구인자와 같은 표현을 써 불일치 원천 차단                                    |
| 마감 시 지원 차단 vs 허용                 | **허용**(현행 정책 유지) — 단, 자동 승계 기능 부재를 문구로 오해시키지 않음                         |
